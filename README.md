# 物流企业碳感知智能决策系统

> 把物流企业的运单数据直接翻译成碳排放量，再翻译成成本与减排方案，在一个**离线可运行的本地网页**上完成决策推演。

[京采命题·运输减碳方案设计] ｜ 数字书院商科拔尖创新人才培养专项支持项目（学生类）

**当前状态**：🚧 开发中 ｜ 流水线骨架已打通（`python -m src.pipeline` → parquet → 前端只读），数据层与核算引擎填实中

---

## 一、这是什么

一个面向物流企业的**轻量碳核算与减排决策工具**。给它三张原始的运单/订单/车辆表，它输出四件事：

1. **算得出来** —— 每一段运输的碳排放量（kg CO₂e），口径来自文献实测数据，不是拍脑袋的系数
2. **看得清楚** —— 哪些车型、哪些线路、哪些月份是排放大户
3. **换得明白** —— 把柴油车换成电动/氢能车，减排多少、多花多少钱、几年回本
4. **说得规范** —— 生成碳会计台账与披露附注，明确核算边界与数据来源

### 解决什么问题

中小物流企业普遍"**有数据、无碳账**"——运单数据躺在 Excel 里，从没被换算成碳；等碳排放管控收紧时，既说不清自己排了多少，也算不清该怎么减排。

现有工具的两端都不好用：大型碳管理软件**贵、重、要联网**；纯咨询报告**不可复算、不可追溯**。

本项目做的是**中间那一层**：轻量、离线、可复算、可解释。**双击一个脚本就能打开，不需要联网。**

## 二、系统能力

五个页面，一个页面回答一个问题：

| 页面 | 回答的问题 |
|---|---|
| **1 基准核算** | 我的车队现在排了多少碳？跑了多少路？速度分布如何？ |
| **2 高排放诊断** | 排放集中在哪？按车型 / 里程段 / 线路 / 月份四个维度看 |
| **3 替代方案** | 换电动车、换氢能车、混合替代，各能减多少？运营上跑得通吗？ |
| **4 成本效益** | 每种方案要花多少钱？补贴有多少？几年回本？敏感吗？ |
| **5 碳会计台账** | 台账怎么记？核算边界、数据来源、假设，怎么披露？ |

## 三、技术栈与纪律

**技术栈（锁定，不讨论替代方案）**

| 层次 | 选型 |
|---|---|
| 语言 | Python 3.10+ |
| 前端 | Streamlit（不写 HTML/CSS/JS；只读结果表，不做计算） |
| 数据存储 | 单文件 parquet（`data/processed/`） |
| 数据处理 | Pandas |
| 图表 | Plotly Express / Streamlit 原生（二选一，全项目统一；当前使用 Streamlit 原生） |
| 环境 | venv + `requirements.txt`（不用 Conda） |
| 版本管理 | Git + GitHub |

**锁定理由**：这套栈的全部依赖可以在一台没网的笔记本上装完，双击脚本就能跑。任何"更先进"的选型都会让答辩现场多一个失败点。

**架构纪律（三文件扁平架构）**

1. **文件越少，找 Bug 越快**：全部业务逻辑收敛在 4 个文件——`src/preprocess.py`（数据层）＋ `src/optimizer.py` / `src/evaluator.py`（算法层）＋ `src/pipeline.py`（调度与打包），不把一件事拆太细
2. **前端只读不算**：`app/` 绝对不允许调用核心算法，只读 `data/processed/` 的结果表，防止卡死
3. **一次准备，全程只读宽表**：数据清洗、三表匹配在 `preprocess.py` 一次性做完，合并成唯一宽表；算法层只看这张宽表
4. **出问题只查三个文件**：路线不对，只查 `preprocess → optimizer → evaluator`
5. **演示兜底**：pipeline 提前把所有结果算好存成 parquet，并配演示用静态数据，保证答辩现场稳定

**五条红线**

1. 不上分布式 / 微服务 / 区块链
2. 不做完整的发票 OCR 识别（仅静态演示入口）
3. 碳金融、低空无人机、多 Agent 协同只写"未来展望"
4. 不私自引入新依赖（新增须全员同意，由 PM 统一改 `requirements.txt`）
5. **原始数据绝不提交进 Git**

## 四、快速开始

```bash
# 1. 创建并激活虚拟环境（需要 Python 3.10+）
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS / Linux

# 2. 安装依赖
pip install -r requirements.txt

# 3. 一键复算（提前算好全部结果表）
python -m src.pipeline

# 4. 启动应用（只读结果表，不参与计算）
streamlit run app/app.py
```

浏览器会自动打开 `http://localhost:8501`。

**先跑 pipeline 再开页面**：pipeline 把全部结果提前算好存进 `data/processed/`，前端只是读表画图，答辩演示最稳。

有原始数据时：把三张赛题表放进 `data/raw/`（见第五章），然后重复第 3 步即可；**没有原始数据也能跑**（`preprocess.py` 内置演示样本）。

> 离线一键启动（双击 `启动.bat` + `wheels/` 离线安装包）为 M4 里程碑目标，尚未实现。

## 六、核心算法与口径

### 6.1 排放因子来源

排放率**不是一条线性公式**，而是**查表 + 线性内插**：

- 来源：吴睿中等（2024）表 8，基于 **VSP（车辆比功率）工况** 的重型货车 CO₂ 排放实测数据
- 基准工况：**VSP = 2 kW/t**（低负荷巡航，样本代表性最强）
- 结构：`车型 × 载重区间 → 排放率 (g/s)`
- 插值示例：30 t 载重落在 14–19 t 档（8.69 g/s）与 44–49 t 档（21.97 g/s）之间，线性内插得 **14.67 g/s**

### 6.2 换算公式

```
式1：每公里排放   F(g/km) = ER(g/s) × 3600 / v        v = 50 km/h
式2：碳排放量     E(kg)   = F(g/km) × 里程(km) / 1000
```

### 6.3 对拍目标（新代码必须复现这些数）

| 指标 | 期望值 | 误差要求 |
|---|---|---|
| 独立路段数 | 33,214 | 精确一致 |
| 总里程 | 4,690,435.81 km | 精确一致 |
| 速度有效样本 | 33,213 | 精确一致 |
| 全样本门到门均速 | 49.57 km/h | ±0.01 |
| 30 t 载重排放率（VSP=2） | 14.67 g/s | ±0.01 |
| VSP=3 平行校验 | 16.53 g/s（偏差 12.68%） | ±0.01 |

> **对拍是这个项目最重要的质量手段**：新代码算出来的数必须和既有计算文件对得上，对不上就是错，不接受"大概差不多"。

### 6.4 成本口径（赛题口径）

```
方案总成本 = 新增购置（补贴后） + 年能耗成本 + 年维护成本
基准总成本 = 0（柴油车已折旧，沉没） + 年能耗成本 + 年维护成本
补贴：纯电动 2 万元/辆；氢燃料电池 20 万元/辆
不计入：人工成本、路桥费、保险费
```

### 6.5 学术诚信声明

- **实测来源**：重型车排放率取自文献[1]（吴睿中等，2024），VSP = 2 kW/t 工况
- **演示假设**：其余车型系数、部分运营参数为**演示性假设**，已在 `docs/08_口径与假设清单.md` 中逐条标注 `【演示假设】`（该文档规划中，尚未落盘）
- **口径可追溯**：每一个数字都能指出它来自哪个配置文件、哪条文献或哪条赛题要求

## 八、一键复算

```bash
python -m src.pipeline
```

流水线只有三步，一步一个文件，任一步失败即中断并报出是哪一段：

1. `preprocess.py` —— 清洗、三表匹配、整合成唯一宽表 → `data/processed/wide_data.parquet`
2. `optimizer.py` —— 排放因子查询、基准碳核算、运营约束 → `data/processed/baseline_carbon.parquet`
3. `evaluator.py` —— 成本效益、热点诊断 → `data/processed/final_report.parquet`

`pipeline.py` 负责按顺序调度并统一产出结果表。**前端只读 `data/processed/`，不参与任何计算。**

**这是答辩现场的生命线**：演示前一晚必须完整跑一次，确认从原始数据到结果表能一键重现。任何改动若使 6.3 的对拍目标超差，即为缺陷，不允许合入。

## 十三、常见问题

**Q：没有原始数据能跑吗？**
能。`src/preprocess.py` 内置演示样本可以跑通完整链路；`data/processed/` 也随仓库提供了示例结果表，可直接启动前端演示。

**Q：为什么不用 MySQL / 云数据库？**
答辩现场不能保证有网。结果直接落成本地单文件 parquet，拷过去就能用。

**Q：Excel 打开导出的 CSV 乱码？**
文件统一用 `utf-8-sig` 编码读写。如果仍乱码，请检查读取方软件的编码设置。

**Q：为什么碳价不是核心功能？**
赛题的成本口径是"购置 + 能耗 + 维护 + 补贴"，没有碳价概念。碳价作为**延展口径**保留，在前端由一个开关切换，不影响赛题主线。

**Q：算出来的数和既有报告对不上？**
先对照第六章 6.1–6.3 的口径与对拍目标。任一项超差都属于缺陷，请开 Issue。
