# 物流企业碳感知智能决策系统

> 把物流企业的运单数据直接翻译成碳排放量，再翻译成成本与减排方案，在一个**离线可运行的本地网页**上完成决策推演。

[京采命题·运输减碳方案设计] ｜ 数字书院商科拔尖创新人才培养专项支持项目（学生类）

**当前状态**：🚧 开发中（阶段一·数据层与碳核算引擎）

---

## 一、这是什么

一个面向物流企业的**轻量碳核算与减排决策工具**。给它三张原始的运单/订单/车辆表，它输出四件事：

1. **算得出来** —— 每一段运输的碳排放量（kg CO₂e），口径来自文献实测数据，不是拍脑袋的系数
2. **看得清楚** —— 哪些车型、哪些线路、哪些月份是排放大户
3. **换得明白** —— 把柴油车换成电动/氢能车，减排多少、多花多少钱、几年回本
4. **说得规范** —— 生成碳会计台账与披露附注，明确核算边界与数据来源

### 解决什么问题

中小物流企业普遍"**有数据、无碳账**"——运单数据躺在 Excel 里，从没被换算成碳；等碳排放管控收紧时，既说不清自己排了多少，也算不清该怎么减排。

现有工具的两端都不好用：大型碳管理软件**贵、重、要联网**；纯咨询报告**不可复算、不可追溯**。

本项目做的是**中间那一层**：轻量、离线、可复算、可解释。**双击一个脚本就能打开，不需要联网。**

## 二、系统能力

五个页面，一个页面回答一个问题：

| 页面 | 回答的问题 |
|---|---|
| **1 基准核算** | 我的车队现在排了多少碳？跑了多少路？速度分布如何？ |
| **2 高排放诊断** | 排放集中在哪？按车型 / 里程段 / 线路 / 月份四个维度看 |
| **3 替代方案** | 换电动车、换氢能车、混合替代，各能减多少？运营上跑得通吗？ |
| **4 成本效益** | 每种方案要花多少钱？补贴有多少？几年回本？敏感吗？ |
| **5 碳会计台账** | 台账怎么记？核算边界、数据来源、假设，怎么披露？ |

## 三、技术栈与纪律

**技术栈（锁定，不讨论替代方案）**

| 层次 | 选型 |
|---|---|
| 语言 | Python 3.10+ |
| 前端 | Streamlit（不写 HTML/CSS/JS） |
| 数据库 | SQLite 单文件 `carbon.db` |
| 数据处理 | Pandas |
| 图表 | Plotly Express / Streamlit 原生（二选一，全项目统一） |
| 环境 | venv + `requirements.txt`（不用 Conda） |
| 版本管理 | Git + GitHub |

**锁定理由**：这套栈的全部依赖可以在一台没网的笔记本上装完，双击脚本就能跑。任何"更先进"的选型都会让答辩现场多一个失败点。

**五条红线**

1. 不上分布式 / 微服务 / 区块链
2. 不做完整的发票 OCR 识别（仅静态演示入口）
3. 碳金融、低空无人机、多 Agent 协同只写"未来展望"
4. 不私自引入新依赖（新增须全员同意，由 PM 统一改 `requirements.txt`）
5. **原始数据绝不提交进 Git**

## 四、快速开始

### 方式 A：一键启动（推荐，答辩现场使用）

**Windows**

```
双击  启动.bat
```

**macOS**

```
双击  启动.command
```

脚本会自动检查 Python、创建虚拟环境、从 `wheels/` 离线安装依赖、启动页面。**全程不需要联网。**

> ⚠️ 首次运行前请确认 `wheels/` 目录已存在且包含依赖包（由项目负责人提供，约 XX MB）。
> 若 `wheels/` 缺失，请改用方式 B。

### 方式 B：手动启动（开发者使用）

```bash
# 1. 确认 Python 版本
python --version          # 需要 3.10 或以上

# 2. 创建并激活虚拟环境
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS / Linux

# 3. 安装依赖
pip install -r requirements.txt

# 4. 获取原始数据（见第五章），放入 data/raw/

# 5. 一键复算（生成中间产物）
python scripts/run_pipeline.py

# 6. 启动应用
streamlit run app/app.py
```

浏览器会自动打开 `http://localhost:8501`。

### 环境自检

仓库根目录的 `app.py` 是**环境验证脚本**，用于确认 Streamlit 是否装好：

```bash
streamlit run app.py
```

能打开页面即表示环境正常。正式应用在 `app/app.py`。

## 六、核心算法与口径

### 6.1 排放因子来源

排放率**不是一条线性公式**，而是**查表 + 线性内插**：

- 来源：吴睿中等（2024）表 8，基于 **VSP（车辆比功率）工况** 的重型货车 CO₂ 排放实测数据
- 基准工况：**VSP = 2 kW/t**（低负荷巡航，样本代表性最强）
- 结构：`车型 × 载重区间 → 排放率 (g/s)`
- 插值示例：30 t 载重落在 14–19 t 档（8.69 g/s）与 44–49 t 档（21.97 g/s）之间，线性内插得 **14.67 g/s**

### 6.2 换算公式

```
式1：每公里排放   F(g/km) = ER(g/s) × 3600 / v        v = 50 km/h
式2：碳排放量     E(kg)   = F(g/km) × 里程(km) / 1000
```

### 6.3 对拍目标（新代码必须复现这些数）

| 指标 | 期望值 | 误差要求 |
|---|---|---|
| 独立路段数 | 33,214 | 精确一致 |
| 总里程 | 4,690,435.81 km | 精确一致 |
| 速度有效样本 | 33,213 | 精确一致 |
| 全样本门到门均速 | 49.57 km/h | ±0.01 |
| 30 t 载重排放率（VSP=2） | 14.67 g/s | ±0.01 |
| VSP=3 平行校验 | 16.53 g/s（偏差 12.68%） | ±0.01 |

> **对拍是这个项目最重要的质量手段**：新代码算出来的数必须和既有计算文件对得上，对不上就是错，不接受"大概差不多"。

### 6.4 成本口径（赛题口径）

```
方案总成本 = 新增购置（补贴后） + 年能耗成本 + 年维护成本
基准总成本 = 0（柴油车已折旧，沉没） + 年能耗成本 + 年维护成本
补贴：纯电动 2 万元/辆；氢燃料电池 20 万元/辆
不计入：人工成本、路桥费、保险费
```

### 6.5 学术诚信声明

- **实测来源**：重型车排放率取自文献[1]（吴睿中等，2024），VSP = 2 kW/t 工况
- **演示假设**：其余车型系数、部分运营参数为**演示性假设**，已在 `docs/08_口径与假设清单.md` 中逐条标注 `【演示假设】`
- **口径可追溯**：每一个数字都能指出它来自哪个配置文件、哪条文献或哪条赛题要求

## 十三、常见问题

**Q：没有原始数据能跑吗？**
能。用 `data/mock/` 的降采样样本可以复现完整链路。

**Q：为什么不用 MySQL / 云数据库？**
答辩现场不能保证有网。SQLite 是单文件，拷过去就能用。

**Q：Excel 打开导出的 CSV 乱码？**
文件统一用 `utf-8-sig` 编码。如果仍乱码，说明该文件不是由本项目的 `src/utils/io.py` 生成的。

**Q：为什么碳价不是核心功能？**
赛题的成本口径是"购置 + 能耗 + 维护 + 补贴"，没有碳价概念。碳价作为**延展口径**保留，在前端由一个开关切换，不影响赛题主线。

**Q：算出来的数和既有报告对不上？**
先看 `docs/08_口径与假设清单.md`。对拍目标写在第六章 6.3 节，任一项超差都属于缺陷，请开 Issue。
