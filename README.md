## 一、这是什么

一个面向物流企业的**段级碳计量与决策装置**。

赛场上别人交一份报告，我们交一台机器：评委现场改一行数据，它能自己报警；从任何一个披露数字，能一路查到具体哪一段运单。

它回答五个问题：

| 页面 | 回答的问题 | 关键产出 |
|---|---|---|
| 首页 | 这是什么，参数怎么调 | 全局参数（λ 内部碳价） |
| 1 基准核算 | 现在排多少、数据多脏 | 总碳排 E₀ + 四类数据标记（含估算值黄框） |
| 2 高排放诊断 | 减排空间在哪 | 四维热点 + 同线碳强度差异 |
| 3 替代方案 | 这条线该派什么车 | 配车方案 + 运营约束校验 |
| 4 成本效益 | 多花多少钱、几年回本 | 成本构成 + 敏感性 |
| 5 碳会计台账 | 怎么记、怎么披露 | 台账六字段 + 附注六要素 |
| 6 路线实验室 | 这条路怎么走、哪条更值 | 高德实时路径 + 4 策略 + 策略级碳账/成本（元） |
| 7 电动化测算（演算） | 电动化每年省多少、多久回本 | 年节省 + 回本月份 + NPV 四分解 + 双口径减碳 |
| 8 车队 TCO 沙盘（演算） | 多条技术路线谁更划算 | NPV 对比 + 元/tCO₂e 减排成本 + 行业口径对照 |

> 第 6 页「路线实验室」不占五页主线：AMap.Driving 实时返回逐点路径（约 0.1 km 一点），
> 路线贴着公路走，带生长动画、镜头缓动、方向箭头与在途回放；4 条策略切换时
> 几何与碳账同步更新（候选路线预计算），路网亮图可核对贴合。
> 碳排/成本/推荐车型仍只读结果表，浏览器不做碳账计算，金额一律按元。
> 设计、踩坑与验证见 docs/29_路线实验室_动态路线与视觉升级.md。
>
> 第 7/8 页是**情景演算页**：评委改参数即时看结论（ChargeMath/FleetTCO 交互精华），
> 逻辑在 `src/scenarios.py`，假设值黄框标注，结果不进闸门——纪律见 `docs/20` §11。

## 三、架构：4 个业务文件 + 1 个契约文件

| 文件 | 职责 | 输入 → 输出 |
|---|---|---|
| `src/preprocess.py` | 三表清洗、关联、打标记、缺失填补 | `data/raw/` → `wide_data.parquet` + `data_quality.json` |
| `src/optimizer.py` | 因子表、双轨计量、段级碳排、C1–C5 约束 | 宽表 → `baseline_carbon.parquet` |
| `src/evaluator.py` | 四维热点、同线带宽、方案对比 | 段级碳排 → `hotspots.parquet` / `od_band.parquet` / `final_report.parquet` |
| `src/pipeline.py` | 顺序调度、出口校验、台账与披露 | 一键复算 + `ledger` / `disclosure` / `kpi` / `gate_report` |
| `src/schema.py` | **契约层**：文件名/列名校验，唯一来源（不读文件、不算业务） | `pipeline`/`services` 共用 |

**三条铁律**

1. **文件越少，找 Bug 越快**：路线不对，只查 1→2→3 三个文件；
2. **一次准备、全程只读宽表**：清洗只在 `preprocess` 做一次；
3. **前端只读不算**：`app/` 里不出现任何业务口径计算，防止答辩现场卡死。

## 四、快速开始

```bash
python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt

python -m tools.launch       # ★ 一键：环境自检 → 可选复算 → 启动应用
                             #   浏览器访问 http://localhost:8501
                             #   Windows 可直接双击「启动.bat」，macOS 双击「启动.command」
                             #   data/raw 为空时自动跳过复算，避免覆盖真实结果表

# 下面两条是 launch 内部做的事，需要单独调时用：
python -m src.pipeline      # 一键复算：宽表 → 段表 → 热点/方案 → 台账/披露/闸门
streamlit run app/app.py    # 只读结果表，直接打开应用（不重算）

# 验收闸门会红 / 能定位失败段
python -m src.pipeline --strict            # 真实数据全绿；演示数据下 5 项 FAIL
python -m src.pipeline --simulate-fail 2   # 期望打印“第 2 段失败”，退出码 1

# 测试套件（CI 同款）：引擎闸门 + 前端 AppTest + 弃用 API 防线
pytest tests/                             # 全绿才算完成；push / PR 时 GitHub Actions 自动跑
```

> **`tools/launch.py` 是演示入口**：`src/pipeline.py` 是引擎（算），`tools/launch.py` 是入口（跑）。
> 启动器**任何一步失败都不阻断启动**——缺依赖会先尝试安装，缺高德 key 自动走离线降级，
> 缺结果表会提示先跑 pipeline。答辩现场用陌生电脑也不至于白屏。
> 完整运行手册见 `docs/27_项目运行手册.md`。
>
> **测试与 CI**：`pytest tests/` = 引擎闸门对拍（退出码 0、PASS 24 / FAIL 0、`--simulate-fail 2` 退出码 1）
> + 首页与八页 AppTest 逐页渲染 + 弃用 API 扫描防线；`.github/workflows/ci.yml` 在 push / 开 PR 时
> 自动跑同一套（Python 3.10 / 3.12 矩阵）。CI 环境没有 `data/raw`，pipeline 自动走演示样本，
> 依赖真数据的五项闸门标 SKIP、因子两项 PASS，退出码仍为 0。闸门用例在临时工作区副本里跑，
