# 项目文件结构规范

**项目**：物流企业碳感知智能决策系统 ｜ **赛题**：京采命题·运输减碳方案设计
**依托**：数字书院商科拔尖创新人才培养专项支持项目（学生类）
**版本**：v2.0 ｜ 2026-10-18 ｜ 主笔：周嬴鑫（PM）
**架构基线**：四文件扁平流水线（`preprocess.py → optimizer.py → evaluator.py → pipeline.py`），前端只读结果表
**配套**：《14_项目实施计划书_v2》《06_任务权限分配与责任矩阵_v2》

> 本文只给结构，不给代码。读完应能回答：**文件放哪、谁写、输入输出是什么。**

## 0. v1.0 → v2.0 变化说明

| # | v1.0（九节点，2026-10-16） | v2.0（本版） |
|---|---|---|
| 1 | `src/` 分 5 个子包、14+ 个文件（data / carbon / analysis / ledger / utils） | `src/` 只有 **4 个文件** |
| 2 | `scripts/run_pipeline.py` + 自定义执行器 | `python -m src.pipeline`（pipeline.py 本体） |
| 3 | `config/` 8 个 csv/yaml 参数文件 | `config/` 预留参数表位（当前参数内置于代码 + `docs/08` 口径清单） |
| 4 | 碳会计独立成 `src/ledger/` + SQLite（db/carbon.db） | 并入 `pipeline.py` 报表段（台账 + 披露），结果统一落 parquet |
| 5 | `tests/` `future/` `data/interim/` `data/mock/` `src/utils/` `Dockerfile` | 全部取消（理由见 §7） |

**继续有效、原样保留的**：数据关联链路与三个坑（§4）、入库策略（§5）、命名规范（§6）。

## 1. 总原则（五条）

1. **文件越少，找 Bug 越快**：全部业务逻辑只有 4 个文件，不新增（新增须 PM 批准）
2. **一次准备、全程只读宽表**：清洗与匹配只在 preprocess 做一次；算法层只看宽表
3. **前端只读不算**：`app/` 不出现业务口径计算（乘系数、折算、成本公式）；允许展示性聚合（sum/count/分组）
4. **原始数据永不入库**：三张表约 3.5 MB，走网盘（.gitignore 兜底）
5. **路线不对，只查三处**：`preprocess → optimizer → evaluator`

## 3. 四个核心文件：职责与输入输出

| 文件 | 主责 | 读 | 写 | 职责与自测 |
|---|---|---|---|---|
| `src/preprocess.py` | 蒿韵丞 | `data/raw/` 三张表 | `data/processed/wide_data.parquet` | 读取（含隐藏 sheet）→ 关联 → 清洗 → 宽表。`python -m src.preprocess` 单跑，打印 33,214 / 4,690,435.81 / 33,213 / 49.57 对拍与关联率 |
| `src/optimizer.py` | 杨盛文 | `wide_data.parquet` | `data/processed/baseline_carbon.parquet` | 排放因子表（内置，文献[1] 表8）→ 查表+线性内插 → 段级碳排；基准汇总；运营约束校验。`python -m src.optimizer` 打印对拍表 |
| `src/evaluator.py` | 曾广 | `baseline_carbon.parquet` | `data/processed/final_report.parquet` | 高排放热点（四维）／新能源替代方案／成本效益与敏感性；成本构成对账（Σ购置净+能耗+维护=总成本）。`python -m src.evaluator` 打印对账 |
| `src/pipeline.py` | 周嬴鑫 | 调度三段 + 报表段 | 同目录结果表 | ① 按序调度三段，任一段失败即中断并报出是哪一段；② **出口对拍闸门**：超差即中断（退出码非 0）；③ **报表段**：台账六字段 + 披露六要素（规格见 15 号文档） |

**报表段说明**：全项目唯一"双人复核"段——周嬴鑫实现，蒿韵丞锁字段与附注口径，曾广审财务表述。台账行数=方案数（3 行量级），**挂"结论"不挂"段"**：不给 36,329 条运单逐段记账。

## 4. 数据关联链路与对拍口径（最容易错，单拎出来讲）

### 4.1 关联链路

```
附件1·订单数据（12,098 行）
  waybill_number（带 -1-1- 后缀，需去掉）
      └─→ 附件2·Sheet1（隐藏表，16,413 行）eclp ↔ tms 桥接
              └─→ 附件1·运单数据（36,329 行，去重后 33,214 条独立路段）
                        └─ vehicle_type_name ─→ 附件2·Sheet2（75 车型：燃油类型 + 载重）
```

### 4.2 三个必踩的坑与口径红线

1. 订单表 `waybill_number` 带 `-1-1-` 后缀 → 去掉后才能与 eclp 匹配；
2. 附件2 Sheet1 是**隐藏 sheet** → 必须显式按 sheet 名读取；
3. 运单表**没有载重字段** → 靠 `vehicle_type_name` 查 Sheet2；Sheet2 载重口径不统一（载质量/总质量），须用 `mass_basis` 标记。

**速度异常处理**：速度 >100 km/h 的 1,298 条（3.9%）为**封/解车时间戳异常**——标记但不删除；核算只依赖里程，删除会改变总里程口径导致对拍失败。

**关联质量报告**：preprocess 必须打印——订单→tms 映射成功数、运单匹配载重成功数、未匹配清单（车型）。关联率 ≥99% 才算过闸。

### 4.3 对拍目标（新代码必须复现，全部写进自测与闸门）

| 指标 | 期望值 | 误差 |
|---|---|---|
| 独立路段数 | 33,214 | 精确 |
| 总里程 | 4,690,435.81 km | 精确 |
| 速度有效样本 | 33,213 | 精确 |
| 全样本门到门均速 | 49.57 km/h | ±0.01 |
| 30 t 载重排放率（VSP=2） | 14.67 g/s | ±0.01 |
| VSP=3 平行校验 | 16.53 g/s（偏差 12.68%） | ±0.01 |

## 6. 命名与格式硬规范

| 对象 | 规范 | 示例 |
|---|---|---|
| Python 模块 | 全小写 + 下划线 | `preprocess.py` |
| 类名 / 函数名 | 大驼峰 / 动词开头小写下划线 | `calc_carbon()` |
| 常量 | 全大写 | `ANNUAL_FACTOR = 3.0417` |
| DataFrame 列名 | 原始中文保留；派生列英文小写下划线 | 原始：`实际行驶里程`；派生：`distance_km` |
| CSV 编码 | `utf-8-sig` | Excel 打开不乱码 |
| 图表文件 | `图{n}_{描述}.png` | `图3_方案成本效益对比.png` |
| 页面文件 | Streamlit 规范 `数字_中文名.py` | `5_碳会计台账.py` |
| 提交信息 | `feat: / fix: / docs: / chore:` | 见 02 号手册 |

## 7. 本版取消的文件与理由（一句话版）

| 取消 | 理由 |
|---|---|
| `tests/` | 自测入口内置进每个模块（`python -m src.xxx` 打印对拍表），对拍即测试 |
| `src/utils/` | 空占位；读写归 preprocess、闸门断言归 pipeline——4 个文件不需要公共库 |
| `scripts/` | `python -m src.pipeline` 即一键复算 |
| `data/interim/`、`data/mock/` | 三段在一趟流水线内完成；演示兜底=入库的 3 张结果表 |
| `db/`（SQLite） | 结果统一 parquet；台账并入报表段 |
| `future/`、`Dockerfile` | 边界声明在 README §十二；离线走 启动.bat + wheels/ |
