# 07｜数据字典（蒿韵丞 / DA）

**状态：** 本轮按 GitHub v2 主线代码与用户提供的赛题原始附件复核生成；用于 `src/preprocess.py` 输出宽表契约。
**主责：** 蒿韵丞（DA）｜**关联复核：** 周嬴鑫（PM）｜**核算输入复核：** 杨盛文（FE）
**当前实现：** 61 个字段；如字段契约变化，应同步更新本文件和 `src/preprocess.py::WIDE_COLUMNS`。

> 本文是数据层说明，不替代赛题说明、排放因子文献或财务口径文件。字段含义以实际源表及当前代码为依据；无法从数据证明的业务含义明确标注为待确认。

## 1. 输入文件与工作表

| 输入 | 工作表 | 实测数据行数 | 当前用途 |
|---|---|---:|---|
| `命题2数据附件1-2023年的订单数据和运单数据.xlsx` | `订单数据` | 12,098 | 订单号、运单号、重量、体积、包裹数、发货/收货地点、妥投时间 |
| 同一附件1 | `运单数据` | 36,329 | 运单号、车牌、车型/编码、里程、封车/解封车时间、起终点网点 |
| `命题2数据附件2-运输车辆的核心信息.xlsx` | `Sheet1`（隐藏） | 16,413 | ECLP–TMS 桥接表；当前主流程不把它当作订单↔运单的必经关联键 |
| 同一附件2 | `Sheet2` | 75 | 车型名称、燃油类型、车辆载重目录 |

当前工作簿的主关联规则是：**订单与运单直接按 `waybill_number（运单号）` 精确关联**。本轮实测两侧唯一运单号集合一致，独立路段口径的 `order_matched` 为 100%。隐藏 `Sheet1` 的 ECLP–TMS 桥接关系仍保留为原始数据资产，但不应替代本工作簿已经可用的直接关联。此前将桥接表作为必经步骤得到的未匹配数，不应直接当作当前主关联的失败率。

车型通过运单的车型名称与附件2 `Sheet2` 的 `车型种类` 精确匹配。本次 68 种运单车型名称均能在 75 条车型目录中找到；但其中只有 62 种命中 `VEHICLE_LOAD_CLASS_MAP`。另外 6 种车型有 845 条运单记录走补充映射规则，且本次这 845 条都属于去重排除行；它们所在的重复组仍可能与保留代表行发生车型/因子冲突。因此，车型目录匹配率 100% **不等于基准车型映射覆盖率 100%**，也不代表重复路段内部不存在冲突。

### 1.1 速度数据来源差异（重要）

- 用户本轮提供的原始附件1运单表没有可识别的“平均速度”列，因此本次速度按 `实际行驶里程 / 正运输时长` 反算；负时长记录不参与速度均值。
- GitHub 随 ZIP 附带的 `docs/21` 提到团队另有 `副本（平均数据）命题2数据附件1...xlsx`，该副本带速度列，官方平均值约 49.5659 km/h。代码现已改为：如同一 `data/raw/` 中存在有“平均速度”列的副本，优先选择该版本；否则使用原始附件，并在 `data_quality.json` 的 `reason/notes` 中写明速度来源。
- 两种输入来源的速度均值不应混成一个口径。本轮原始附件反算均值为 **49.5127 km/h**，与副本官方统计约 49.5659 km/h 不完全相同；应以团队冻结的数据源和规则为准。

### 1.2 原始表关键字段

**订单数据：** 订单号、运单号、商家订单号、客户编码、订单重量（kg）、订单体积（cm³）、总包裹数、发货/收货省市、妥投时间。当前清洗重点保留源订单号缺失、包裹数缺失和发货城市缺失的痕迹。

**运单数据：** 运单号、车牌号、车型编码、车型名称、实际行驶里程（km）、封车时间、解封车时间、封车网点、解封车网点，以及某些版本中可能存在的平均速度列。

**车型目录：** `Sheet2` 的 `车型种类`、`燃油类型`、`车辆载重`。`车辆载重`原始值存在载质量、整车总质量或准牵引总质量等不同口径，不可不加判断地直接作为排放因子输入。当前代码通过 `VEHICLE_LOAD_CLASS_MAP` 和载重口径规则生成 `load_t`、`vclass`、`mass_basis`。

## 2. 关联、去重与清洗规则

1. **订单关联：** 去空格后的运单号精确匹配；匹配标志在用运单号代理缺失订单号之前计算，避免把代理值误当成真实订单号。
2. **车型目录：** 车型名称与 `Sheet2` 名称精确匹配；目录匹配率与重复路段内部的车型一致性分开统计。
3. **段级去重键：** `waybill_no + plate + dist_km（四舍五入至 2 位小数）+ departure/arrival 时间（截到秒）`。若时间不完整，回退为 `waybill_no + plate + dist_km + origin|dest`。若运单号或车牌缺失，不自动判为重复。
4. **去重行为：** 宽表保留全部 36,329 行，用 `flag_dup=1` 标记重复组中不进入段级基准计算的行；当前因子核算表排除这些重复行。原始行号保留在 `source_waybill_row`。
5. **不覆盖源数据：** 缺失字段即使为满足宽表数值类型暂时填 0，也必须由对应缺失标志解释；异常时间原值保留，不擅自将原始时间戳改正确。
6. **无发票字段时：** 当前赛题原始附件没有发票号、发票状态或发票金额，必须使用空值/不适用状态，不得构造发票金额。
7. **速度：** 优先使用源数据实际提供的速度列；不存在时用里程除以正时长。异常时间不能产生实测速度，标记为 `invalid_time_excluded`。

### 4.3 重要限制：指标复现不等于车型冲突已消失

当前段级基准仍遵循项目既定 `flag_dup` 规则，重复组按原始行顺序保留第一条代表行，因此可以复现 33,214 段、总里程和当前 E₀。为避免隐藏该风险，本轮代码新增两个行级字段：

- `flag_vehicle_conflict=1`：该路段所在重复组有车型名称/代码、燃油、载重映射或载重口径冲突。当前去重后代表行共有 **2,077 条**被标记。
- `flag_factor_conflict=1`：该路段所在重复组的排放因子输入 `(vclass, load_t)` 不一致。当前去重后代表行共有 **814 条**被标记。
- `flag_load_mapping_fallback=1`：该行车型没有命中 62 类基准车型映射。本次共有 845 条原始行、涉及 6 种车型，全部属于去重排除行；不能因为这 845 行不直接进入当前基准计算，就忽略它们与保留代表行之间可能存在的冲突。

**因此，E₀=4,502,042.41 kg 是现行主线算法可复现的基准值，但由于存在 814 组因子输入冲突，不能把这部分路段视为已经获得唯一真实车型证据。** 需要团队决定是否用原始业务规则/参考明细来裁定代表值，或把冲突组做独立敏感性分析；在此之前，不应声称车型冲突已全部解决。

### 4.4 本次不属于数据错误的状态

- 订单与运单直接关联率 100% 是本工作簿按运单号直接连接的结果；附件2隐藏 `Sheet1` 桥接表不是这条主关联链的必经环节。
- 车型目录匹配率 100% 只意味着车型名称能找到 Sheet2 条目，不代表同一路段重复行的车型值一致。
