## 0. 本版变更摘要（v2 → v3）

| # | 变更 | 原因 |
|---|---|---|
| 1 | 赛道锚点：揭榜挂帅 → **主体赛·发明制作 A 类** | 交付物从"一份方案"变成"一台可演示、可验证的装置" |
| 2 | 产品逻辑：展示链 → **决策闭环** | 从"算出来给你看"变成"这条线该派什么车、差多少钱、怎么入账" |

| 6 | 取消 `src/utils/`、`tests/`、`scripts/`、`config/*.yaml` | 文件越少，找 Bug 越快；零新增依赖 |
| 7 | 排期：4 周（3 冲刺 + 1 留白） | 满足"一个月之内 + 留一周空余" |

## 1. 业务逻辑全景

### 1.1 一句话

> **给它一笔运单，它告诉你这条线该派什么车、多花或少花多少钱、碳账怎么记；给它一批运单，它告诉你你自己的碳数字误差有多大、误差从哪来。**

### 1.2 五个问题 = 五个页面

| 页 | 回答谁的什么问题 | 关键输出 |
|---|---|---|
| 首页 | 这是什么 + 全局参数（λ、口径开关） | 项目摘要 + 实时参数 |
| 1 基准核算 | 现在排多少、跑多远、数据多脏 | E₀ + 里程 + 三类 FLAG 统计 |
| 2 高排放诊断 | 空间在哪：四维热点 + **同线带宽** | 1.50× 中位差的路线清单 |
| 3 替代方案 | 这条线该派什么车、运营跑不跑通 | 配车方案 + 约束校验 |
| 4 成本效益 | 多花多少钱、λ 一变推荐换不换 | 成本构成 + Pareto |
| 5 碳会计台账 | 怎么记、怎么披露 | 台账六字段 + 附注六要素 |

### 1.3 决策闭环（**不是**展示链）

**① 计量（双轨）→ ② 诊断（同线带宽）→ ③ 决策（配车 + λ）→ ④ 成本效益 → ⑤ 碳账入账 → ⑥ 校准回流（回到 ①）**

上一版是单向的"算—看—换—算钱—记账"；本版是闭环，**回流的那根箭头就是上一场录音里"他们给我们数据"那句话**。

### 1.4 三条实证依据（2026-10-18 用 33,214 段实算）

| 发现 | 数值 | 用途 |
|---|---|---|
| 里程↔碳、时长↔碳 高度同向 | r = 0.961 / 0.750 | 证明"宏观配权重"退化——**砍掉权重滑块的理论依据** |
| 同一 OD 内 速度↔碳强度 几乎无关 | 232 组，中位 r = −0.004，仅 24% 组 `r<−0.3` | 证明"段级才出现决策空间"——**段级计量的正当性** |
| 同一 OD 换车型，碳强度差 | 中位 **1.50×**，P90 2.08×，最大 4.01× | 证明"试线试不出、换车才值钱"——**产品价值的落点** |
| 310 个可比较 OD 对覆盖率 | 碳排 83.8% / 里程 74.7% | 证明不是边角样本 |
| 同线换最低碳车型的上界 | −29.8%（该块）/ 占 E₀ 的 25.0% | **须标注"未约束运力"，是结构性带宽而非可减排量** |

## 2. 工程师建议的采纳与修正

### 2.1 采纳（8 条，逐条落到文件）

| # | 建议 | 落地方式 |
|---|---|---|
| 1 | 业务逻辑收成 3 个文件 | `optimizer` / `evaluator` / `pipeline` + 数据层 `preprocess`，共 4 个 |
| 2 | 跟"车怎么跑"有关的全在 optimizer | §3.2 O1–O7 |
| 3 | 跟"算碳算钱"有关的全在 evaluator | §3.2 E1–E6 |
| 4 | 报表（台账/披露）放 pipeline | §3.2 G3–G4 |
| 5 | 提前算好存 parquet，前端只读 | `data/processed/` 三表 + `app/services.py` 只读 |
| 6 | 前端绝不调核心算法 | 页面内**零业务计算**（允许 sum/count/分组） |
| 7 | 脏数据不抛 Exception | 全部 `try/except + 兜底值 + FLAG`，见 §2.3 |
| 8 | 前端给标记行加黄框 | `app/components/flags.py` 统一渲染 |

### 2.2 修正（2 条，需 PM 拍板并写入 08 号）

**修正一：算碳因子不放在数据层，留在 optimizer。**
工程师建议"清洗、匹配、算碳因子全在 preprocess"。**不采纳这一句**：因子是**口径**不是**数据**——它会随文献更新、随国标采标变（ISO 14083 正在采标）。放数据层，改一个因子要重跑清洗；放 optimizer，改因子只重算碳排，宽表不动，对拍立刻告诉你漂了多少。

**修正二：FLAG 不是"填补缺失值"，而是"标记重复/异常/口径换算"。**
见 §2.3——你们的数据缺得少、重得多。

### 2.3 数据体检结果（2026-10-18 实测，决定 FLAG 设计）

| 检查项 | 实测 | 判定 |
|---|---|---|
| 车型：运单 68 种 vs 附件2 登记 75 条 | 未匹配 **0** 种 | 不会 KeyError |
| 里程缺失 / 时间为空 | **0 / 0** | 不会 NaN 崩 |
| 订单号带 `-1-1-` 后缀 | **12,095 / 12,098**（3 条不带） | `[:-5]` 切片会切错这 3 条 |
| 运单号带 `-1-1-` 后缀 | **0 条** | 两表口径相反，必须分别处理 |
| 解封早于封车（负时长） | 1 条 | 算出负速度 |
| 速度 > 100 km/h | **1,298 条（3.9%）** | 标记不删 |
| 运单 36,329 → 独立路段 33,214 | 去重 **3,115 行（8.6%）** | **最大的雷：不去重则 E₀ 高估约 9.4%，且不报错** |

**三类 FLAG（宽表固定三列，取值 0/1 + 原因字符串）**

| 列名 | 触发 | 前端呈现 | 是否保留 |
|---|---|---|---|
| `flag_dup` | 同 运单+车牌+里程+起点+终点 | 灰底 + "已去重 3,115 行" | 剔除（另存口径统计） |
| `flag_anomaly` | 速度 >100 或 <1、时长 ≤0、里程为 0 | 黄框 "时间戳异常" | **保留不删**（删了改总里程口径，对拍必挂） |
| `flag_basis` | 附件2 载重为"载质量/总质量/准牵引"三类 | 黄框 "载重按总质量换算" | 保留 + 显示原值与换算值 |
