## 1. 第一次跑（干净电脑）

### 1.1 装依赖

```bash
cd "D:/2027大挑网站合并版本"
pip install -r requirements.txt
```

> **必须 Python 3.8+**。本机实测 3.12.6（pandas 3.0.6 / streamlit 1.66.0 / pyarrow 26）全绿。
> **streamlit 下限 1.56.0**（2026-10-22 起）：`width` 参数与 `st.iframe` 自该版本起全量就绪，
> 分别替代已弃用的 `use_container_width` 与 `streamlit.components.v1.html`；低版本请先升级。

### 1.2 配高德 key（可跳过，跳了就走离线模式）

```bash
python -m tools.amap_setup        # 交互式引导，粘贴即可
python -m tools.amap_setup --check # 只看状态（含真调 REST 验证）
```

三个文件各填什么，见 `config/README.md` §1.1。**填错位是本项目最高频的坑**，
助手会真调高德 REST 验证，能按错误码精确诊断：

| 错误码 | 含义 | 助手会提示 |
|---|---|---|
| `10001 INVALID_USER_KEY` | 服务端**查不到**这把 key | "多半把『安全密钥』当 key 复制了" |
| `10009 USERKEY_PLAT_NOMATCH` | 服务端认得它，但**平台不对** | "这是 JS API 的 key，应放 amap_js_key.txt" |
| `10000 OK` | 正确 | "调用成功（天安门 → 坐标）" |

> **实战案例**：三把 key 曾经填成 `Web服务key←安全密钥 / JSkey←JSkey / 安全密钥←Web服务key`，
> 外部表现是"Web 服务 key 报 INVALID_USER_KEY"——靠交叉测试（把三个值分别打到 REST）
> 才定位到是**整体错位**，不是某一把填错。助手的交叉验证就是为这类情况准备的。

### 1.3 预取真路线（可跳过，跳了就走 haversine 估算）

```bash
python -m tools.route_fetch        # 约 5 分钟（246 网点地理编码 + 310 条驾车规划）
```

- 246 个网点地理编码 + 310 条热点 OD 驾车规划；
- 结果落 `data/processed/route_od.parquet`（**已入库，团队共享**）；
- **第二次跑零 API 调用**（走缓存）——所以每人只需要跑一次，或者直接用仓库里的。

> **限流说明**：高德对并发请求会静默限流（实测并发 6 只有 40% 成功率），
> 所以本工具用**全局令牌桶**限到 QPS 2.0、并发 2——246 个网点约 4.5 分钟。
> 这是刻意的：地理编码失败会让网点退化成城市级近似坐标，路线精度下降。
>
> **实测成功率**：246 个网点解析 242 个（98.4%），310 条 OD 拿到 100% 真路线。

> **几何抽稀口径（2026-10-22 起生效）**：路线折线按 Douglas–Peucker（RDP）保形抽稀，
> 上限 1,500 点——同样点数下能保留弯道与互通立交的走向。
> 旧实现是固定步长抽样（1,375 km 只留约 400 点、约 3.4 km 一个点），离线底图上是"抽象折线"。
> **已入库的旧缓存不会自动升级**：`route_fetch` 对已缓存的 od_key 直接跳过（第二次跑零 API 调用），
> 要按新口径生成必须 `python -m tools.route_fetch --refresh`（约 310 次 API 调用，QPS 2.0 约 3 分钟）。
> 在线主视觉用高德实时几何（约 1.2 万点），不受缓存影响；缓存几何只服务第 6 页的离线兜底。

### 1.4 启动

```bash
python -m tools.launch
```

## 3. 启动器会检查什么

`python -m tools.launch` 的自检输出长这样：

```
  ✓ Python 版本      Python 3.12.6
  ✓ 依赖包           streamlit 1.66.0 · pandas 3.0.6 · numpy 2.5.4 · pyarrow 26.0.0 · plotly 7.1.0
  ✓ 核心数据表          5 个核心结果表就绪
  ✓ 对拍闸门           PASS 22｜FAIL 0｜SKIP 0
  ✓ 高德 key         三把 key 齐备 → 在线底图 + 真路线可用
  ✓ 路线表            路线表 310 条（高德真路线 295 / 离线兜底 15）
```

**只有"核心数据表"和"对拍闸门"不通过才是硬伤**（会提示先跑 `python -m src.pipeline`），
高德 key 和路线表缺失只提示不阻断——因为那两条都有离线兜底。

### 3.1 路线情景软校验（T7，附在闸门里）

跑 `--with-routes` 时，闸门会多出三项软校验（**不参与退出码**，L1 的问题不许拖垮 L0）：

```
  路线情景软校验（T7 · 不参与退出码）：
    ✓ PASS 路线距离 vs 实测里程：路线/实测倍数中位 0.97（偏离 16.6%，目标 ≤20%，比对 310 个 OD）
    ✓ PASS 路线碳 vs 基准碳：中位偏差 -0.10%（阈值 ±50%，比对 13493 段）
    ✓ PASS 热点 OD 真路线覆盖率：真路线 295 / 310（95.2%，目标 ≥95%）
```

> **S1 为什么用"倍数偏离"而不是 |Δ|/km**：宽表里程是附件给的**规划里程**，
> 高德是**真实道路距离**，两者口径本就不同。用 |Δ|/km 会把口径差异误判成数据错误
> （实测 20.5%，虚高一倍）。改用倍数后：真路线偏离 15.7%，错配 OD 偏离 3246%——
> 差 200 倍，20% 阈值既能放过正常差异，又能抓住真正的错乱。

## 4. 三层降级（答辩现场断网怎么办）

```
① key 未配 / 路线表不存在  → 第 6 页路线实验室整体跳过 + 提示生成命令
                              其余七页照常演示
② key 已配但现场断网        → iframe 内 #fallback 文字提示（8 秒超时）
                              页面保留"离线示意图"切换
③ 完全无网                 → 第 6 页画 Plotly 离线底图（矢量示意，不请求瓦片）
                              路线用 route_od.parquet 缓存几何；无 key 时缓存由
                              haversine×1.28 估算生成，口径与 docs/20 §2 一致
```

**永不出现的状态**：白屏、灰图、Exception、页面卡死。

**答辩前必做**：拔网线开一遍八页（`docs/22` R2，C4 硬指标）。

## 5. 数据流：一句话记住

```
data/raw ──preprocess──> wide_data.parquet ──optimizer──> baseline_carbon.parquet
                                                                       │
                        ┌──────────────────────────────────────────────┤
                        │                                              │
                  evaluator                                        O8 route_carbon
                        │                                              │
      hotspots / od_band / final_report                    route_carbon.parquet (L1)
                        │                                              │
        ledger / disclosure / kpi ──pipeline──> gate            route_select.parquet (L2)
                                                                        │
tools/route_fetch.py ──高德 REST──> route_od.parquet ──────────────────┘
                                                                              │
                                                       app/ 前端只读 ◄────────┘
```

**L0 主口径永不动**：E₀ = 4,502,042.41 kg，闸门精确命中。
L1（路线情景）/ L2（λ 决策）是**增量层**，页面逐处标注口径，不混算。

## 6. 排障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: streamlit` | 依赖没装 | `pip install -r requirements.txt` |
| 页面报"该表还没就绪" | 结果表缺失 | `python -m src.pipeline` |
| 闸门 FAIL，退出码 1 | 口径漂移 | 看 `data/processed/gate_report.json` 的 `targets` 逐项对 |
| 地图白屏 | securityJsCode 顺序错 | `_AMapSecurityConfig` 必须在 SDK script 之前 |
| 地图灰块 | 断网 | 切"离线示意图"；业务无损 |
| `INVALID_USER_KEY` | key 填错位 | `python -m tools.amap_setup` 重新验证 |
| `USERKEY_PLAT_NOMATCH` | 服务平台选错 | 拿 Web服务 key 加载了 JS SDK，重新添加【Web端(JS API)】key |
| 路线表覆盖率低 | 地理编码失败（虚构网点名） | 正常；失败网点自动降级为城市级近似坐标 |
| `route_fetch` 卡住不动 | 网络慢 | 加 `--limit 20` 先试跑；已成功的会进缓存不重复抓 |
| 端口 8501 被占 | 另一个 streamlit 在跑 | `python -m tools.launch --port 8502` |

## 7. 团队协作约定

1. **环境统一**：README 里的"标准启动命令"以本文为准（`python -m tools.launch`）；
2. **key 只在个人机器**：三个 `config/amap_*.txt` 已 gitignore，**不要**把 key 贴进群或提交；
3. **路线表入库共享**：`route_od.parquet` 已进仓库，**不需要每个人重跑** `route_fetch`；

   `grep -R "read_parquet" app/` 只允许命中 `app/services.py`。

## 9. 常见疑问

**Q：路线表为什么要预取，不直接调高德？**
A：三个理由——① key 不进前端（前端只读铁律）；② 答辩现场零 API 调用、不受网络影响；
③ 路线数据可审计可复现（parquet 入库，任何人能复现同样的数字）。

**Q：没配 key 还能演示吗？**
A：能。第 6 页路线实验室回退 `route_od.parquet` 缓存几何 + Plotly 离线底图；
缓存无 key 时由 haversine×1.28 估算生成（与 `docs/20` §2 同口径）。
闸门 S1 会报 FAIL（诚实：估算精度确实到不了 10%），这不影响主口径 PASS 22。

**Q：`tools/launch.py` 和 `src/pipeline.py` 有什么区别？**
A：`pipeline` 是**算**（产出结果表、跑闸门）；`launch` 是**跑**（自检 + 调 pipeline + 起 Streamlit）。
前者是引擎，后者是演示入口。

**Q：为什么 `app/pages/` 下没有地图代码？**
A：内容与容器解耦（`docs/25` §3.1）。地图逻辑在 `app/components/amapview.py`，
业务面板在 `app/components/decision_panel.py`，页面只做取数/摆组件/传参三件事。
第 6 页「路线实验室」（2026-10-22 上线）就是这么长出来的：一个 page 文件调用同一组件，零重写；
第 3 页只保留入口提示，同一张高德图不画两遍。
