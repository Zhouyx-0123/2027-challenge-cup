## 2. 三种启动方式

### 方式 A：双击 `启动.bat`（最省事，推荐给答辩/演示）

自动完成：找 Python → 装依赖 → 自检 → 有 raw 附件才复算 → 起服务 → 浏览器打开 `http://localhost:8501`。
停止：窗口里按 `Ctrl+C`。

> **macOS / Linux**：双击 `启动.command`（或终端 `bash 启动.command`）。
> 逻辑与 Windows 版一致：按依赖可用性挑解释器。

> ⚠️ **已修的一个老问题**：原 `启动.bat` 的横幅里有一个裸 `&`，
> cmd 会把它当命令分隔符，导致启动时飘一行 `'决策' is not recognized...`。
> **不影响功能**（复算、启动都正常），但答辩现场看到报错很扎眼 —— 已修。

## 4. 生成/重算 OSM 基线（可选）

**基线数据已经生成好了**（`data/processed/route_baseline_sh_bj_steps.parquet` + `..._summary.json` 已入库），
所以普通使用者**不需要跑这一步**。只有在换 OD、换车型、换因子版本时才需要重新生成：

```bat
python -m tools.route_baseline --origin 121.315087,31.014995 --dest 116.664264,39.909698 --coord gcj02 --vehicle 30t_tractor --load 30
```

- `--coord gcj02`：输入是 GCJ-02 坐标（高德口径），工具内部转 WGS-84 后再喂 OSRM。**这是前置强制工序**，跳过会偏 500–800 m。
- 需要**联网**，走公共 OSRM（`router.project-osrm.org`），单次 20–25 s。
- 产出：D2 逐 step 表（21 字段）、D3 summary JSON、原始响应 `outputs/route_baseline/raw_osrm.json`（不入库）。
- 换车型目前会**显式报错**（第一版只实现 `30t_tractor`），不静默套用错误因子。

当前基线数字（实测）：

```
距离 1189.97 km ｜ 时长 816.2 min ｜ 碳排 1256.6 kg（1.2566 t）｜ 65 step
道路等级里程占比：高速 86.29% / 国道 11.24% / 城市道路 0.91% / 省道 0.88% / 匝道 0.67% / unknown 0.00%
端点吸附误差：24.5 m / 47.9 m
```

## 5. 底图：默认免 token，配了天地图 token 会自动切换

Tab② 的 OpenLayers 组件支持 **WMS / WMTS / XYZ** 三类源。底图**按 token 有无自动选择**：

| 条件 | 底图 | 几何基准 | 效果 |
|---|---|---|---|
| **无 token（当前）** | **高德栅格 XYZ** | GCJ-02 | **服务端已把路线几何转成 GCJ-02 对齐，零偏移**；暗色化后与页面主题统一 |
| 有 token | 天地图 WMTS | CGCS2000 | 与 WGS-84 差 < 1 m，零偏移；瓦片质量更高 |

> **当前状态：不需要任何 token 就有底图。**
> `config/tianditu_token.txt` 还是占位符，但 Tab② 已经有完整底图了。

想换成天地图（更"正"的官方底图）：

1. 到 <https://console.tianditu.gov.cn/> 申请「开发资源」，拿到 token；
2. 填进 `config/tianditu_token.txt`（替换整个占位符文本）；
3. 刷新页面即可，底图右上角可手动切换。

### 为什么高德底图也能精确对齐（原先的说法过严）

早先文档写"不能用高德底图，因为 GCJ-02 硬叠会偏 500–800 m"。**准确的说法是：不是不能用，而是要先做基准对齐。**

转换由服务端 `app/components/basemap_align.py` 完成，**只改坐标不改数值**：
距离 / 时长 / 碳排全部来自 parquet，一个字节都不动。详见 `docs/38` §2。

### 断网时怎么办

- **底图瓦片加载失败** → 右上角提示，路线矢量照常可读；
- **OpenLayers CDN 加载失败** → 显示提示，但**右侧 65 条 step 列表、图例、页脚照常显示**
  （这三块不依赖 OL，已做降级解耦）；
- **完全断网** → 天地图/高德都用不了，路线矢量 + 列表仍完整。

## 9. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: pandas` | 用了系统默认的 Python 3.13 | 用 `Python312\python.exe` 绝对路径，或 `py -3.12` |
| 打开 `/6_路线实验室` 跳回首页 | Streamlit 路由是中文路径 | 用 `/路线实验室`（URL 编码）或直接点导航栏「路线」 |
| Tab② 底图空白、只剩路线 | 高德瓦片被网络拦截 / CDN 抖动 | 右上角可切底图；配天地图 token 更稳（见 §5） |
| Tab② 整页只剩一句"底图不可用" | OpenLayers CDN 加载失败 | **右侧 65 条 step 列表与图例仍会显示**（已做降级解耦）；换网络重试 |
| Tab② 图例显示 `motorway / trunk` 英文 | payload key 撞名（历史 bug，已修） | 刷新页面；若出现请报 issue（`payload["labels"]` 专供等级中文名映射，路名标注用 `roadNames`） |
| Tab① 高德地图空白 | 高德 JS key 失效或网络拦截 | 确认 `config/amap_js_key.txt`；缺 key 时自动走离线兜底 |
| 想重跑基线但很慢 | 公共 OSRM 限流 + 长距离 | 正常 20–25 s；别并发跑 |
| 端到端测试间歇性失败 | 公共 CDN 偶发慢 | 脚本已内置 3 轮重试（每轮 25 s + 切 Tab 触发重渲染）；连跑 3 次稳定通过 |
