## 3. 数据输入：最高优先级

### 3.1 当前真实入口

~~~text
data/raw/
  附件1：订单 + 运单 .xlsx
  附件2：车辆核心信息 .xlsx
        ↓
python -m src.pipeline
        ↓
data/processed/*.parquet/json
        ↓
streamlit run app/app.py
~~~

现状：

- 没有上传页面；
- preprocess.py 优先识别“附件1/附件2”，也有通用 CSV/Excel 回退；
- 缺少面向用户的模板、逐列校验、错误定位、输入报告；
- 用户不知道“文件放哪、列叫什么、错了怎么办”。

### 3.2 目标用户流程（不改前端）

~~~bash
# 1. 放文件
data/raw/附件1-订单与运单.xlsx
data/raw/附件2-车辆信息.xlsx

# 2. 先校验，不计算
python -m tools.import_data --validate

# 3. 校验通过后复算
python -m src.pipeline

# 4. 启动
python -m streamlit run app/app.py
~~~

### 3.3 必须定义的输入契约

文件：

- 附件1：订单 Sheet + 运单 Sheet；
- 附件2：车型 Sheet；
- 支持 .xlsx/.xls/.csv/.parquet；
- 文件名可配置，不强制中文名。

运单/订单必需列：

- waybill_number 运单号；
- vehicle_number 车牌；
- vehicle_type_name 车型；
- 实际行驶里程（km）；
- departure_time 封车时间；
- arrival_time 解封车时间；
- 发货/收货网点；
- 订单重量/体积/妥投时间。

校验规则：

- 文件可读、Sheet 可识别；
- 必需列齐全，缺列报“文件/Sheet/列名”；
- 运单号唯一性、订单↔运单 join 率；
- 里程/重量/时间为数值或可解析；
- 负时长、速度 >130、速度 ≤1、缺失速度单独标记；
- 车型匹配率、未匹配车型清单；
- 重复运单数、去重后物理行程数；
- 任何硬错误不覆盖 data/processed，不产生半成品。

输出：

~~~text
data/processed/input_report.json
  status: pass/fail
  rows / waybills / trips
  join_rate / vehicle_match_rate
  errors[] / warnings[]
~~~

错误提示示例：

~~~text
[FAIL] 附件1 / 运单数据：缺少列“实际行驶里程（km）”
[FAIL] 第 128 行：arrival_time 早于 departure_time
[WARN] 61 条速度 <1 km/h，将按 50 km/h 处理
[WARN] 7 个车型未在附件2匹配
~~~
