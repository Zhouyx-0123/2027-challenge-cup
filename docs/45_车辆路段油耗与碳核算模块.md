**日期：** 2026-10-25 ｜ **状态：** v1.0 · 内核 + CLI + 测试已落地 ｜ **落位：** `src/fleet_efficiency.py`（碳计算层）
**配套：** `docs/44_发票智能录入_设计与接口对接.md`（发票识别与支出法碳核算）、`docs/20_工程落地与踩坑对照.md` §11（演算页纪律）、`docs/08_口径与假设清单.md`

---

## 1. 一句话

把**发票实测油量**、**高德路网实距**、**VSP 模型**三样东西拧成一把尺子，
给每辆车、每条路一个**可审计**的油耗标签，并把碳摊回路段与车辆。

---

## 2. 落位与纪律

| 项 | 位置 | 说明 |
|---|---|---|
| 内核 | `src/fleet_efficiency.py` | 纯函数、可单测；只读结果表与 `config/`；**不写 `data/processed`、不进闸门、不进 kpi** |
| CLI | `tools/fleet_efficiency_report.py` | 只读分析工具，产出三份审计报告到 `outputs/`（已 gitignore） |
| 测试 | `tests/test_fleet_efficiency.py` | 32 项 |
| 配置 | `config/fuel_price_history.json` | 外部油价表，**默认空**（同 `config/invoice_spend_factors.json` 纪律） |

**为什么不叫 `app/pages/`**：这是碳计算，属引擎层。页面只读不算的纪律不适用于它，但它同样不写结果表、不进闸门 —— 它是**分析层**，不是对拍链路。

**口径唯一**：柴油因子只从 `config/calc_factors.json` 读（2.63 + 0.53 = 3.16 kg CO₂/L），
外部油价只从 `config/fuel_price_history.json` 读，**两者都不在代码里硬编码**（有测试守护）。

## 3. 四条轨道

```
发票(金额/油量/单价) ──► 油量 ──┬──► 油量直算碳排                  （实测）
                              └──► 与该车行程配对 ──► 实测百公里油耗
里程(运单) + 车型 + 因子表 ───────────────────────────► 理论百公里油耗（法定轨）
里程 + VSP 模型(kg_co2_phys) ──────────────────────► 理论百公里油耗（VSP 轨）
高德路线(实距/时长/拥堵灯) ─────────────────────────► 路段特征

实测 vs 理论 = 油耗偏差 = 车牌标签 + 审计线索
多车样本在同一条路上的偏差中位数 = 路段系数 → 碳摊回路段与车辆
```

**核心价值**：油量是**实测值**，因子表是**估算值**。两者的关系是**交叉校验**，不是替换。
差异本身就是诊断信号（车型错配 / 里程错报 / 油耗异常）。

---

## 4. 油价这一环为什么必须有

有些发票只给金额、不给加注数量。要把金额变成油量，必须有当时的油价：

```
油量 = 金额 ÷ 油价
```

油价三级来源，优先级从高到低：

| 级 | 来源 | 强度 |
|---|---|---|
| ① | 票面单价 `unit_price`（已加进 OCR 提示词与台账列） | 最强，自证 |
| ② | 金额 ÷ 油量（自洽反推） | 可与①互相校验，差 >5% 判 needs_review |
| ③ | 外部历史油价表 `config/fuel_price_history.json` | **默认空** |

③ 默认空是刻意的：没有可核查来源的油价，宁可不换算、标 `needs_review`，也不塞行业均值糊过去。
这与 `config/invoice_spend_factors.json` 的"默认不放任何金额因子"是同一条纪律。

## 5. 油箱周期：油量怎么落到路段上

**定义**：同一车牌的相邻两次加油之间，是一箱油覆盖的行程。
某张发票的油量覆盖 `[该发票日期, 下一张发票日期)` 内该车的全部行程；周期内油量按**里程比例**分摊到各段。

按里程分摊的物理依据：油耗率是里程的函数（L/100km），按里程分摊等价于给每段一个恒定的等效油耗率，
符合"一箱油走完全程"的直觉，且可复算、可审计。

没有发票覆盖的段：`allocated_liters = NaN`，`allocation_status = "no_invoice_cover"`，不参与实测口径。

## 6. 车牌标签与置信度

```
实测百公里油耗 = Σ分摊油量 ÷ Σ里程 × 100     （仅统计被油量覆盖的段）
理论百公里油耗 = Σ法定轨碳排 ÷ Σ里程 × 100     （同口径段，取法定轨）
偏差           = (实测 − 理论) ÷ 理论
```

标签分档：≤±10% 正常｜±10~25% 偏高/偏低（关注）｜>±25% 异常·偏高/偏低。

**置信度按被油量覆盖的里程分档**（不是按段数）：

| 覆盖里程 | 置信度 |
|---|---|
| < 50 km | `insufficient`（明确写"样本不足，不判定"，不硬判） |
| 50–200 km | `low` |
| 200–1000 km | `medium` |
| ≥ 1000 km | `high` |

> 为什么必须分级：实测**每车每月只有 1 段、73 km**（中位），但头部车是 870 段 / 91,244 km。
> 不带置信度的标签就是在多数车上自欺欺人。

## 7. 路段模型（两级）

| 级 | 系数 | 依据 | 何时采用 |
|---|---|---|---|
| **一级（先验）** | 该路段 VSP 轨 g/km ÷ 法定轨 g/km 的里程加权比 | **VSP 模型本身**（速度对排放的修正），物理依据充分，**不是拍脑袋的系数** | 默认 |
| **二级（实测标定）** | 该路段各车「实测百公里油耗 ÷ 同段理论百公里油耗」的中位数 | 真实发票 | 样本段数 ≥ 5 时覆盖一级 |

路段碳排修正：`co2_attributed_kg = kg_co2 × route_factor`；系数缺失则不修正并标 `factor_applied=False`。

## 8. 审计线索

每条线索带完整证据链：车牌、月、实测/理论油耗、偏差、覆盖段数与里程、置信度、关联发票号、判定规则。

**线索与数据缺口分开**：
- 有发票证据但偏差超阈值 / 覆盖不足 → **审计线索**，进清单；
- 完全没有发票覆盖 → **数据缺口**，单独统计（`data_gap_summary`），不进清单。

否则没有发票时整张表都会变成"待办"，把真线索淹掉。

## 9. 实测发现的三个物理事实（必须知道，否则一定算错）

### 9.1 VSP 轨在低速段会爆

因子表隐含的是 50 km/h 基准，而 VSP 修正是"瞬时排放率随速度偏离 50 km/h 而变"：

```
VSP/法定 = mult(VSP) × 50 ÷ 速度
```

实测（33,214 段）：

| 速度档 | 段数 | 里程 km | VSP/法定 倍数 |
|---|---|---|---|
| ≤20 km/h | 4,937 | 151,838 | **4.51** |
| 20–30 | 4,414 | 163,124 | 1.77 |
| 30–40 | 4,333 | 293,208 | 1.33 |
| 40–50 | 4,352 | 345,453 | 1.09 |
| 50–60 | 4,982 | 684,191 | 0.93 |
| 60–80 | 8,560 | 2,652,764 | 0.83 |
| >80 | 1,389 | 396,521 | 0.60 |

逐段差异 p50=4.8% / p95=316.5% / p99=**1130%**，但**按里程汇总仍只有 +2.93%**（与 README 主账一致）。

**结论**：理论基准取**法定轨**；VSP 轨只作高速段参考，低于 30 km/h 标 `vsp_applicable=False`。
直接把 VSP 轨当"百公里油耗"用，低速段会离谱到 4 倍以上。

### 9.2 高德路线的关联键是 `od_site`，不是 `od_key`

- `od_key` 是**城市级**（`上海|深圳`），与高德路线表（`上海车墩集货分拣中心|广州增城集货分拣中心`）**命中率 0%**；
- `od_site` 是**网点级**，命中率 **40.6%**（13,493/33,214）。

高德只预取了 310 条热点 OD，命中不了的段 `route_km = NaN`，**不做任何填补**。

### 9.3 必须在物理行程口径上算，否则理论油耗被低估 N 倍

段表里 `kg_co2` 是**分摊后**的值（`kg_co2 = kg_co2_gross × allocation_share`），
而 `trip_km` 在该行程的**每一个运单行上都是整趟里程**。
直接在运单行上算 g/km → 里程算重 N 倍（N = `waybill_assoc_count`）→ 理论百公里油耗被低估 N 倍。

**实测对照**：修正前某重卡理论值算成 **1.20 L/100km**（物理上不可能），修正后 **24.03 L/100km** ✓。

主账 E₀ 用的就是物理行程口径（`src/pipeline.py` 的 `build_kpi` 对 `trip_id` 去重），
**本模块必须同口径**，否则两边对不上账。
`to_physical_trips()` 负责这件事，`prepare_segments()` 是标准入口。

## 12. 端到端验证（真实段表 + 仿真发票）

用真实段表里里程最多的 4 辆车，造 4 张仿真发票（100% / 145% / 72% / 100% 理论油量）：

| 车 | 仿真 | 实测 L/100km | 理论 L/100km | 偏差 | 标签 |
|---|---|---|---|---|---|
| 沪DL1971 | 100% | 24.026 | 24.027 | −0.00% | ✅ 正常 |
| 苏BAZ028 | 100% | 24.028 | 24.027 | +0.01% | ✅ 正常 |
| 沪FP5231 | 72% | 17.314 | 24.027 | −27.94% | ✅ 异常·偏低 |
| 苏UF069L | 145% | 18.105 | 12.486 | +45.00% | ✅ 异常·偏高 |

路段模型同步命中：样本 ≥5 段的路段系数 = 1.4500（正是苏UF069L 的 145% 仿真偏差）；
样本 <5 段的自动退回 VSP 先验并标注 `factor_source=vsp_prior`。

**说明**：仿真发票只用于验证链路可跑通与产出形状（`invoice_no` 以 `DEMO-` 开头），
不代表真实发票数据，**不写入仓库**。
