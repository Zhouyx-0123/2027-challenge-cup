五个真正会"堵住企业"的缺口

其余缺口（可观测、台账版本链、审批流）在路线图后段处理。这五个不补，系统只能停在"演示级"。

缺口现状证据不补的后果优先
无身份与权限 全仓无 login/jwt/oauth 命中 谁都能看全部数据、谁都能改参数 P2
无数据库 只有 *.parquet / sensor_data.csv / outputs/*.csv 高频写入、单用户覆盖写、多人并发全都不成立 P1
无任务调度 复算靠手工 python -m src.pipeline 数据不会自动变新，企业系统退化成演示系统 P1
外部 API 无治理 amap_client.py 固定 15s 超时，无重试/缓存/配额 高德配额打爆、账单失控、演示时当场失败 P1
传感器接口无鉴权 server.py:20 CORS "*"，POST 只校验字段 局域网任意设备可伪造读数写入数据 P0

分模块怎么继续做得更好

每张卡三到四步，都是在现有页面上做加法，不改口径、不改引擎闸门。

首页概览

现状：静态读 kpi/gate/ledger → 指标卡 + 决策面板 + 步骤卡；重叠问题已用 CDP 量盒模型验收（7/7）。

  1. 信任信号上首屏：run_log.generated_at + 闸门 28/28 + source=real 常驻显示——现在这些只在 JSON 里。
  2. 概览 → 作业看板：决策面板接三类可行动项（闸门 FAIL / 方案目标差距 / 传感器越限），可点击跳转。
  3. 异常优先排序：用四类 flag_* 标记做待处理清单，按影响排放量排序，不按行数。
  4. 角色化视图（P2 后）：管理层 / 车队调度 / 财务 / 审计只读，各看各的。
首屏能回答"数是什么时候算的、过没过闸门、我该管哪三件事"。

发票数据感知

现状：OCR → 解析 → 与油量/碳账对账；MOCK_MODE 纪律清晰，mock 必标注"演示用"；产物含车牌发票号，永不入库。

  1. 置信度闭环：从"有没有 mock 标记"升级为"识别置信度 → 自动入账 / 转人工复核"，低置信字段进复核队列。
  2. 成本与配额治理：识别次数/金额预算、同票去重缓存、退避重试、超额熔断。
  3. 异步化：请求线程不再等网络识别，提交→队列→结果可取→通知。
  4. 数据分级：原图加密留存、导出默认掩码车牌、原图与结构化结果分离。
任何一条入账记录可回到原图与识别原文；重复发票不重复计费。

云边端硬件监控

现状：ESP32 → Flask → 追加 CSV（线程锁）；字段校验完整；PM 严格隔离在碳账外；1000ppm 阈值仅为一条线。

  1. 设备身份与准入（最明确的安全敞口）：设备注册表 + 请求签名校验，非法设备 401，CORS 从 * 收敛。
  2. 文件 → 时序库：高频下 CSV 追加不可用；原始读数设 TTL，长期只留窗口聚合。
  3. 断网续传与乱序：现在时间戳由服务端生成，补传必失真；改设备端带时间戳+序号，服务端幂等去重。
  4. 设备健康度 + 告警闭环：在线率/丢包率看板；越限 → 告警 → 处置 → 复盘。
未注册设备 100% 被拒；断网 24h 补传数据不重不乱。

减碳路线沙盘

现状：高德 JS 地图 + 碳价滑条三线敏感度图 + Q-learning/NSGA-II；真路线覆盖 295/310；seed=42 硬编码已实测退化。

  1. 算法变离线实验（最值钱一步）：固定输入集 + 多 seed 批量跑 + 记录 Q 表/收敛曲线 + 模型版本 + 晋级门槛，达标才允许上线到页面。
  2. 高德缓存与配额：按 OD 对 + 因子版本缓存路线结果，配额账本 + 限流 + 熔断，降级要明示状态。
  3. 情景快照：参数 + 代码版本 + 因子版本 + run_id 可完整回放；沙盘结果永不进台账。
  4. 多人并发：长任务入队 + task_id 取回 + 并发上限，避免互相抢 CPU。
同 seed + 同输入 100% 复现同一 Q 表；退化种子被门槛自动拦下。

碳核算与台账

现状：台账六字段 + 披露六要素 + 因子版本 + 双轨碳；闸门同源自校验（台账总碳 = 首页总碳）；已有审计轨迹。

  1. 账本化：现在每次复算覆盖写。改 append-only 版本链，修正走红字冲正分录。
  2. 编制→复核→批准：批准后不可改，只能出修订版；审批人/时间/意见落审计表。
  3. 披露与第三方核查：六要素映射 GHG Protocol / ISO 14064 / GB-T 32150；一键导证据包。
  4. 披露自动化：按期间自动生成 + 到期提醒 + 变更留痕。
任意历史期间台账可原样重现；证据包能独立复算出同一 E₀。

引擎层 src/（全站地基）

现状：四段式 pipeline + run_log + 28 项闸门 + schema 唯一契约；全量复算 14.9s，当前规模无压力。

  1. 幂等 + run_id 版本化（P0 就做）：产出 runs/<run_id>/，"当前生效 run"用指针表示——越早做越省事。
  2. 闸门变发布门禁：FAIL → 不发布、不更新生效指针，gate_report 挂发布记录。
  3. 计算与存储分离：算→纯函数服务、存→仓储层。这是能否把计算搬进队列的分水岭。
  4. 参数治理闭环：参数随 run 固化，历史结果可按当期参数重放。
所有"多版本、可追溯、可回放"能力的地基——它改目录结构，越晚迁移越贵。

分阶段路线图

工期为建议值，最终排期由 PM 定。每阶段都以硬判据收尾，不以"功能做了"收尾。

  1. P0 · 交付形态

    建议 2–3 周

    目标：能交给别人部署、能安全跑。

    • run_id 版本化 run 目录；Dockerfile + compose；配置/密钥外置分层；反代 + TLS
    • CI 扩展：构建镜像 → 推 registry → 部署 → 跑现成冒烟脚本（verify_pages / verify_nav / verify_sliders / verify_dashboard_layout）
    • data/raw 备份脚本 + 一次恢复演练；传感器加设备鉴权，CORS 收敛

    验收：全新机器 30 分钟起服务 · 冒烟全绿 · 零明文密钥 · 未注册设备被拒 · 闸门 FAIL 不发布

  2. P1 · 数据平台化

    建议 3–4 周

    目标：数据会自己变新，长任务不阻塞页面。

    • Postgres：传感器 / 任务 / 审批 / 审计 / 台账版本链；任务队列 + 调度器
    • 高德缓存 + 配额账本 + 熔断；算法离线实验管线（多 seed + 晋级门槛）
    • 幂等复算 + 计算存储分离（为 P2/P3 的审批与版本链腾位置）

    验收：定时复算产出新 run 与新指针 · 长任务不阻塞 · 配额耗尽自动降级且明示 · 同 seed 100% 复现

  3. P2 · 身份与权限

    建议 2–3 周

    目标：多人安全共用。

    • 企业 SSO 反代认证（本系统不建账号，符合 docs/43 边界）
    • 应用级角色：管理员 / 碳管理 / 车队调度 / 审计只读；按公司·车队的数据行级隔离
    • 全操作审计表；改参数、批台账可追溯到人

    验收：不同角色可见性不同 · 越权 100% 被拒并记审计

  4. P3 · 产品闭环

    持续

    目标：从"看数"到"管事"。企业化的后半程是运营，不是开发。

    • 首页作业看板 + 告警闭环（企微/钉钉/邮件）；台账 append-only + 三态审批
    • 披露生成器 + 证据包导出；大屏与移动端；SLA 监控与容量压测

    验收：一次碳核查全流程无需手工拼文件 · 台账任一历史期间可原样重现

需要 PM 拍板的 6 件事

其中第 1 条是硬前提：不放开依赖约束，P1/P2 无法实施。

01放开依赖约束（现由 PM 统一管、禁加依赖）
建议放行最小集：psycopg / redis(或 celery) / prometheus-client + 容器构建件。走反代认证则连 authlib 都不需要。不放开则数据平台化无从下手。
02部署形态与客户环境
建议先定单企业内网单实例 + compose，可平滑升多副本。决定 P1/P2 的深度与多租户是否要做。
03认证方式
建议企业 IdP 反代认证，本系统不建账号——与 docs/43「V1.0 不添加登录界面」不冲突，成本最低。
04数据出域约束
建议敏感数据不出内网，只输出脱敏聚合报表。直接决定 DB 与对象存储选型、能否上云。
05旧 11 页前端是否恢复（当前 5 页）
建议不恢复，按 5 页演进。注意 docs/43 按 8 页写，口径需同步修订，否则文档与实现对不上。
06Q-learning 三条修复是否实施
建议实施①改种子策略 + ②奖励加动作归因，并由 P1 的实验门槛自动把关。属"改口径"，需点头。

四条不可破的红线

平台化改造最容易顺手破坏的就是这四条——请写进代码评审清单。

口径零改动 + 闸门先行

不得改变 E₀ / KPI / 台账的计算结果；所有改造仍须过同一套 28 项闸门，FAIL 不得发布生效版本。

Mock 纪律与通道隔离

演示数据必须显式标注；实时演示通道的结果永不进入 E₀ / KPI / 闸门 / 台账。

原始数据永不入库 + 分级

data/raw 不入 Git、不进结果区；发票/车牌级数据加密留存、导出脱敏、最小权限、可审计。

令牌唯一真源

视觉令牌仍只认 theme.py 的 :root；新增页面/组件不得另起 CSS 变量。
