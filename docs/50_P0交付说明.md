## 1. 配置与密钥分层（`src/config.py`）

**问题**：`.gitignore` 只能挡"进不进 git"，挡不住"进不进镜像层""进不进日志""进不进备份包"。

**分层顺序**（固定、可解释）：

| 序 | 来源 | 适用场景 |
|---|---|---|
| 1 | 环境变量 `<KEY>` | compose / CI / 容器注入 |
| 2 | 环境变量 `<KEY>_FILE` 指向的文件 | Docker secret、K8s Secret |
| 3 | `SECRET_DIR` 目录下的同名文件（默认 `/run/secrets`） | 标准挂载约定 |
| 4 | 仓库 `config/<file>` | 本机开发（.gitignore 已挡） |
| 5 | 默认值 | 没有就是没有，**不编造** |

**改造的 6 处读取点**（行为向后兼容，环境变量仍然最优先）：

- `src/routing/amap_client.py` → 高德 Web 服务 Key
- `src/routing/amap_js.py` → 高德 JS API Key + 安全密钥
- `app/live_services.py` → DeepSeek Key（发票识别）
- `tools/invoice_ocr.py`、`tools/route_fetch.py`、`tools/launch.py` → 同上

**新增能力**：`src.config.known_secrets()` 只返回"配了没有 + 从哪儿来的"，**永远不含值**——
给部署自检页、CI 断言和 `tools/verify_p0.py` 用。

```bash
python -c "from src import config; import json; print(json.dumps(config.describe(), ensure_ascii=False, indent=2))"
```

## 2. run 版本化 · 生效指针 · 发布闸门（`src/run_manifest.py`）

### 2.1 问题

改造前 `python -m src.pipeline` **原地覆盖** `data/processed/`：算坏了页面读到的就是坏表；
"上个月报出去的账当时长什么样"已无法回放。

### 2.2 三件东西

- **run_id**：`<时间戳>-<输入指纹前 8>`（输入指纹 = 原始附件清单 + 因子配置内容 + 代码版本）
- **快照**：每次执行的产物存一份到 `data/processed/_runs/<run_id>/`
- **生效指针**：`data/processed/current_run.json` 指向**当前对外生效**的那一次

### 2.3 发布语义（铁律）

> `data/processed/` 下的**数据表永远等于当前生效版本**。

| 情形 | 动作 | 页面看到什么 |
|---|---|---|
| 闸门 PASS | 快照 → 更新生效指针 → 记索引 | 新数据 |
| 闸门 FAIL | 记失败快照 → **回滚**到上一生效版本 → **指针不动** | 上一版好数据 |
| 中途异常 | 同上（`reason=stage_failed`） | 上一版好数据 |

例外：`run_log.json` 与 `gate_report.json` 记录的是**最近一次执行**（失败也留痕），不参与回滚——
运维必须看得见失败。

### 2.4 用法

```bash
python -m src.pipeline                      # 复算 + 闸门 + 发布（失败自动回滚）
python -m src.pipeline --runs-keep 20       # 保留最近 20 个快照（默认 10）
python -m src.pipeline --adopt-current      # 不重算：把现有结果认领为生效版本
python -m src.pipeline --strict             # 演示数据也强制对拍（验证闸门会红）
```

`--adopt-current` 是企业化上线时的"补出生证明"：仓库里已有一批过闸门的结果表，
用它快照一次并写指针，之后每次复算才走正常发布流程。**它不重算、不改一个数字。**

## 3. 传感器接入鉴权（`src/device_auth.py` + `server.py`）

### 3.1 改造前 / 改造后

| | 改造前 | 改造后 |
|---|---|---|
| 身份 | 无（任何人可 POST） | `X-Device-Token` + 设备注册表，**fail-closed** |
| CORS | `origins: "*"` | 白名单 `SENSOR_ALLOWED_ORIGINS`，默认空 = 不发跨域头 |
| 限流 | 无 | 每设备每分钟 N 次（默认 60），超限 429 + `Retry-After` |
| 审计 | 无 | 每次调用一行 JSONL（**不记令牌**） |
| 缺 `flask_cors` | 服务起不来 | 可选依赖，缺了照常起（只是不发跨域头） |

### 3.2 设备注册表

`config/devices.json` —— **只存令牌的 sha256 摘要**，明文不落盘、不进版本库：

```json
{"version": 1, "devices": [{"device_id": "PDM-GZ-001", "token_sha256": "…", "enabled": true, "note": "1 号冷链车"}]}
```

### 3.3 登记 / 轮换 / 吊销

```bash
python -m tools.device_tokens list
python -m tools.device_tokens add    --device-id PDM-GZ-001 --note "1 号冷链车"
python -m tools.device_tokens rotate --device-id PDM-GZ-001     # 旧令牌立即失效
python -m tools.device_tokens remove --device-id PDM-GZ-001
```

`add` / `rotate` 时终端**只打印一次明文令牌**，请立刻抄到设备端。

### 3.4 设备端怎么改（ESP32 / MicroPython）

```python
import requests
requests.post("http://<主机>:5000/api/upload_sensor",
              json={"device_id": "PDM-GZ-001", "co2": 812.3, "temp": 24.1},
              headers={"X-Device-Token": "<明文令牌>"})
```

> **答辩演示临时退路**：设备来不及改时，设 `SENSOR_AUTH=0` 关闭鉴权（启动会打醒目告警，
> `/api/health` 也会标出来）。**部署到企业环境前必须打开。**

### 3.5 数据文件路径统一

接收端与读取端共用 `src/sensor.py:sensor_data_path()`：

- 默认：仓库根 `sensor_data.csv`（行为不变）
- 容器部署：`SENSOR_DATA_FILE=/app/data/sensor_data.csv`（落在挂载卷，容器重建不丢）

```

```

| 服务 | 端口 | 作用 |
|---|---|---|

## 6. 备份与恢复演练

```bash
python -m tools.backup --label nightly            # 打一份备份
python -m tools.restore_drill backups/2026…        # 演练：解包 + 逐文件 sha256 校验
python -m tools.restore_drill <dir> --restore-to D # 真恢复（默认不覆盖已有文件）
```

**收什么**：`data/raw`（不可再生的原始证据，必收）、`config/*.json` 因子、代码（`src/app/tools/server.py`）、
非敏感 `outputs/*.json`。
**不收什么**：密钥（`--include-secrets` 才收，且控制台醒目告警）、`data/processed`（可重算）、
含车牌/发票号的产物（**无开关，永久排除**）。

产物：`<备份目录>/backup.tar.gz` + `manifest.json` + `SHA256SUMS.txt`（可 `sha256sum -c`）。
归档是**确定性**的（mtime/uid/gid 归零），同内容两次备份的数据成员字节一致。
解包前会拒绝含绝对路径或 `..` 的成员（路径穿越防护）。

## 10. 已知限制（**未验证项如实列出**）

1. **容器与 CI 未在本机真跑**——本机没有 Docker，镜像 build、`compose up`、Caddy 证书签发、
   `docker-smoke` 作业端到端**均未真实执行**，只做了 YAML 解析与人工审读。首次部署请按
   `deploy/README.md` 的验证清单逐条走一遍。
2. **数据库、任务队列、多租户仍未做**——属于 P1/P2，本次未触碰。
3. **台账仍是覆盖写**（不是 append-only 账本）——属于 P3，本次只做了 run 级版本化。
4. **算法种子退化问题未修**（`route_sandbox.py` 硬编码 `seed=42`）——属"改口径"，仍待点头；
   但 P0 的 run 机制已经能记录每次的 seed 与 run_id，为后续做实验门槛打了底。
5. **`flask_cors` 本机未安装**（requirements.txt 已声明）——服务端已改成可选依赖，不影响启动；
   若要在浏览器里跨域访问，需要装上它。
