## 2. 两条部署路线

### 路线 A：Windows 原生部署（**今天就能用，不依赖 Docker**）

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\start-native.ps1
```

一条命令同时起：

- 决策台 `http://10.104.105.152:8501`（健康检查 `/_stcore/health`）
- 传感器网关 `http://10.104.105.152:5000/api/upload_sensor`（健康检查 `/api/health`）

特点：端口占用会先核对**到底是谁在监听**（不会把别人的服务误判成自己起的）、
PID 写 `logs/native.pids.json`、日志写 `logs/`、可重复执行（已在跑就只打印地址）。

配套：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\stop-native.ps1          # 停
powershell -ExecutionPolicy Bypass -File deploy\windows\install-services.ps1     # 注册开机自启（需管理员）
powershell -ExecutionPolicy Bypass -File deploy\windows\firewall.ps1            # 放行 8501/5000（限 LocalSubnet，需管理员）
powershell -ExecutionPolicy Bypass -File deploy\setup_windows.ps1 -Native        # 一体化入口
```

### 路线 B：Docker 容器化（需重启一次，且取决于宿主）

**当前进度（2026-10-27 16:14）**：WSL2 与虚拟机平台已启用（dism 返回 3010 = 需重启生效），
Docker Desktop **4.97.0 已安装**（CLI 29.9.2 + compose 插件就位）。
**还差最后一步：重启一次**，daemon 才能起来。

```powershell
# —— 现在执行（幂等，已装过会自动跳过）——
powershell -ExecutionPolicy Bypass -File deploy\install_docker.ps1
# —— 重启一次 ——
# —— 重启后执行 ——
powershell -ExecutionPolicy Bypass -File deploy\setup_windows.ps1 -Finish
```

`-Finish` 会依次做：`docker version` → `docker compose config -q` → `docker compose build` →
`up -d` → 健康轮询 → 跑 4 个冒烟脚本（`verify_pages / verify_nav / verify_sliders / verify_dashboard_layout`）。

> **重启会中断当前运行的决策台与传感器服务**——重启后用原生脚本或 compose 重新拉起即可。
> docker 命令刚装完**不在当前终端的 PATH 里**，新开一个终端即可（或直接用完整路径）。

**风险提示（必须知道）**：本机在 Hyper-V 虚拟机里，若宿主**没有**把 VT-x/AMD-V 透传给本机，
WSL2 与 Docker Desktop 会报 `0x80370102`（虚拟化未启用）。此时 **路线 A 仍然完全可用**——
这也是为什么两套都要配。

## 3. 硬件接入（ESP32 → 接收端 → 页面）

### 3.1 链路

```
ESP32(MH-Z19B + DS18B20)
   │  HTTP POST  http://<主机>:5000/api/upload_sensor
   │  Headers: X-Device-Token: <明文令牌>
   │  Body:    {"device_id":"PDM-GZ-001","co2":812.3,"temp":24.1,"ts":...,"seq":...}
   ▼
Flask 接收端（server.py）——鉴权 → 限流 → 校验 → 追加 sensor_data.csv → 审计
   ▼
Streamlit 硬件监控页（只读 CSV，不回写 E₀/KPI/闸门）
```

### 3.2 物料清单

| 物料 | 型号 | 接口/电压 | 关键词 | 价位 |
|---|---|---|---|---|
| ESP32 开发板 | WROOM-32E / S3 | 3.3V，USB 5V 供电 | 淘宝「ESP32-WROOM-32E 开发板」 | ¥25–45 |
| CO₂ 传感器 | MH-Z19B（或 SGP30 / SCD41） | UART 9600 / 5V | 淘宝「MH-Z19B 二氧化碳传感器」 | ¥30–60 |
| 温度传感器 | DS18B20（或 BME280） | 1-Wire / I²C 3.3V | 淘宝「DS18B20 防水温度探头」 | ¥5–12 |
| 杂项 | USB 线、杜邦线、4.7kΩ 上拉、面包板 | 5V ≥1A | 淘宝「杜邦线 20cm」 | ¥10–40 |

接线：`MH-Z19B VCC→5V、GND→GND、TX→GPIO16(RX2)、RX→GPIO17(TX2)`；
`DS18B20 VCC→3V3、DQ→GPIO4、需 4.7kΩ 上拉到 3V3`；
I²C 类 `VCC→3V3/5V、SDA→GPIO21、SCL→GPIO22`。

### 3.3 令牌下发三步

```bash
# ① 主机登记（明文令牌只打印一次）
python -m tools.device_tokens add --device-id PDM-GZ-001 --note "1 号冷链车"
# ② 抄下明文令牌
# ③ 写进设备端：
#    Arduino：复制 hardware/esp32/config.example.h → config.h，填 DEVICE_TOKEN（config.h 不入库）
#    MicroPython：把令牌写进设备上的 /device_token.txt
```

批量下发（多台车）：

```bash
python -m tools.device_tokens batch --prefix PDM-GZ --count 5 --out outputs/device_tokens.csv
```

> 导出的 CSV **含明文令牌**，绝不入库（`.gitignore` 已挡 `*.csv`）。

### 3.4 联调顺序（先软后硬）

```bash
# ① 不接硬件，先用探针把链路跑通
python -m tools.sensor_probe --register          # 登记探针设备并打印令牌
python -m tools.sensor_probe --expect-401        # 期望：未授权被拒（401）
python -m tools.sensor_probe --token <明文>      # 期望：上报成功（200）
python -m tools.sensor_probe --token <明文> --readback   # 期望：读数已落盘

# ② 再接硬件，烧录固件（见 hardware/README.md）

# ③ 打开 http://localhost:8501/sensor 看读数曲线
```

**注意**：一旦 `sensor_data.csv` 里有真实读数，页面就不再显示演示序列——
想回到答辩演示序列，删掉该文件即可。

### 3.5 固件行为

- **零外部库**：只用 ESP32 核心（`WiFi/HTTPClient/Preferences/Wire/time`），JSON 用 `snprintf` 手拼。
- **令牌存 NVS**（`sensor/token`），回落 `config.h`；串口命令 `set <token>` 运行时写入。
- **断网缓存**：环形缓冲 50 条，**NVS 持久化**（掉电不丢），恢复网络后按原顺序补发，补发仍带 `ts`+`seq`
  （为 P1 时序库的幂等去重预留）。
- **失败策略**：401 → **停止重试**并打印"令牌无效"；429 → 读 `Retry-After` 按其等待；
  5xx/网络失败 → 指数退避（1s→2s→4s…上限 60s），读数入队待补发。

## 4. 排障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| POST 返回 401 | 没带令牌 / 令牌错 / 设备未登记 | `python -m tools.device_tokens list` 核对；ESP32 端核对 `config.h` |
| POST 返回 429 | 每设备每分钟超限（默认 60） | 看响应头 `Retry-After`；调 `SENSOR_RATE_LIMIT_PER_MIN` |
| 连不上（超时） | 防火墙 / 不同网段 / IP 变了 | `deploy\windows\firewall.ps1` 放行；ESP32 指向 `10.104.105.152` |
| 400 且提示数值超范围 | co2 ∉ [0,100000] 或 temp ∉ [-50,100] | 检查传感器量程与单位 |
| CO₂ 恒为 400 | MH-Z19 未预热 | 上电后等 60 s 再读 |
| 温度恒为 0 | 传感器接线/供电/DS18B20 时序余量 | 换 BME280 更稳；核对接线 |
| 时间戳不对 | 设备没对上 NTP | 串口看时间；或服务端时间为准（当前服务端生成时间戳） |
| 页面显示"演示数据" | `sensor_data.csv` 为空 | 正常：真读数接入后自动切换 |
| Docker 起不来 `0x80370102` | 宿主未透传嵌套虚拟化 | 走**原生路线**（§2 路线 A） |
