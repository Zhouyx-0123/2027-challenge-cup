# 54 · 碳数据输出格式与前端落地方案

> 对象：碳会计线 A0–A6 交付（`carbon_ledger/`）→ 是不是要进前端、怎么进
> 结论：**进前端**。形态是「碳核算与台账」页内的**第二个只读 tab**（不新增第六页）；
> 六块内容全上；**页面不提供任何写入或审批控件**。
> 前置文档：`docs/53`（接入评估与口径对齐）｜实现：`src/carbon_ledger_export.py`、`app/components/carbon_ledger_panel.py`
> 日期：2026-10-29

---

## 1. 一句话

**碳账的企业价值不是那个 2.44 吨，是"这份账能不能对外报、凭什么、还差什么"。**
所以前端要显现的是**判定**，不是另一套数字。

---

## 2. 链条拆解：工科 OBD+GPS 数据 → 碳会计指标 → 最终产物是什么

### 2.1 四层

```
① 工科实测流            OBD+GPS 原始流（2 秒级时间序列）
   src/obd_gps.py → data/processed/obd_*.parquet
        │
        │  活动量层：activity_value / distance_km / speed_kmh / altitude_m
        ▼
② 活动数据底稿          Activity_Data（51 字段，碳账与财务账共用）
   carbon_ledger/a2_activity_data/activity_data_template.xlsx
        │
        │  核算层：X = Activity_Value × EF_Value ；Y = X / 1000
        ▼
③ 碳账主账              Trip_Detail（42 列 × 12 条）—— **唯一加总来源**
   carbon_ledger/a4_ledger/carbon_ledger_main.xlsx
        │  资格层：AP2 判定 + AN2 物理趟次去重 + AO 人工审批
        ▼
④ 汇总与台账            Monthly / Annual（模拟）· Formal_*（0 行）· Quota_Ledger · Evidence_Index
```

### 2.2 最终产物是什么

**不是数字，是「资格判定」。**

| 产物 | 实测值 | 含义 |
|---|---|---|
| `Trip_Detail` | 12 条 `simulated` 行，合计 **2.439298 tCO₂e** | 明细，唯一加总来源 |
| `Monthly_Summary` | 2026-10 = 5 行 / 0.844132；2026-11 = 4 行 / 1.14178；2026-12 = 3 行 / 0.453386 | 模拟测试汇总，标 `SIMULATED_TEST_SUMMARY_NOT_FORMAL` |
| `Annual_Summary` | 12 行 / **2.439298 tCO₂e** | 同上，年度口径 |
| `Formal_Monthly_Summary` / `Formal_Annual_Summary` | **0 行 / 0 t / `NO_APPROVED_ROWS`** | **正式汇总资格：无合格正式行** |
| `Quota_Ledger` | 期初 1.0 + 购入 0.2 = 可用 1.2；已用 2.439298；结余 0；**缺口 1.239298 t** | 配额台账，`Approval_Status=not approved` |
| `Evidence_Index` | 13 条（12 行级凭证 + 1 条因子来源） | 证据链；**凭证文件 0/13 存在** |
| `Validation_Rules` / `Test_Cases` / `Pressure_Test_Cases` | 14 条 / 15 项 / 19 项（19 PASS） | 自证 |
| `Pending_4_Vehicle_Data` | 仅状态行，无数值 | 四车样例按负责人指示暂不处理 |

> ⚠️ **「0 行正式汇总」≠「排放为零」。** 它说的是"没有合格正式行"。
> 页面必须原样表达这个意思，不能简写成零排放。

### 2.3 三张关键公式（主账内）

| 位置 | 公式 | 作用 |
|---|---|---|
| `X` 列 | `=IF(OR(L2="",T2=""),"",L2*T2)` | 排放量 kgCO₂e = 活动量 × 因子 |
| `Y` 列 | `=IF(X2="","",X2/1000)` | 折成 tCO₂e |
| `AM` 列 | `=UPPER(车辆\|日期\|活动类型\|TEXT(里程,"0.000")\|TEXT(货重,"0.000")\|活动量\|单位)` | 物理趟次去重指纹 |
| `AN` 列 | 去重指纹重复 → `BLOCK_POSSIBLE_PHYSICAL_DUPLICATE` | 去重控制 |
| `AP` 列 | 9 个谓词的 AND | 正式汇总资格（见 §5.2） |

### 2.4 OBD 侧能喂进碳账的是什么

字段字典（51 字段）已经把 GPS 列为 `distance_km` / `speed_kmh` / `altitude_m` 的数据来源；
`activity_value` 的来源是「燃油/电力凭证、实测装置或核准模型」。

**即：OBD+GPS 实测通道天然就是碳账活动量层的上游**，对应关系：

| 碳账字段 | OBD/GPS 侧来源 | 就绪度 |
|---|---|---|
| `activity_value`（L） | OBD 累计油耗差分 / 瞬时油耗积分 | 实测优先，发票次之 |
| `distance_km` | GPS 里程 | 已有 |
| `speed_kmh` | GPS 速度 | 已有 |
| `altitude_m` | GPS 高度 | 已有 |
| `ambient_temp_c` | OBD 冷却液温度（近似） | 已有（近似） |
| `cargo_t` | 主链路货重 | 已有 |
| `trip_id` / `segment_id` / `waybill_id` / `run_id` | 主链路 | 已有 |
| `factor_value` | `config/calc_factors.json`（TTW）+ 碳账 WTW 登记 | 待登记 |

**当前真正的堵点不是"OBD 喂不进碳账"，而是三样外部资料没到位**：
正式排放因子文件、真实凭证（发票/运单/读数）、财务账底稿。

## 3. 前端结论

### 3.1 从企业视角：显现什么

企业从这套交付里要的是四句话，前端必须让这四句话**一眼可见**：

| 企业的问题 | 前端回答 | 落在哪一块 |
|---|---|---|
| 这份账能不能对外报？ | `NO_APPROVED_ROWS` + 逐条阻断原因 | ① 状态条 + ② 判定链 |
| 凭什么？ | 每行的 Evidence_ID ↔ 凭证文件是否真的存在 | ④ 证据链索引 |
| 换个��算还是不是这个数？ | 规则卡 + 14 条控制规则 + 19 项压力场景 | ⑥ 规则与自证 |
| 还差什么？ | 51 字段就绪度 + 配额缺口 | ⑤ 就绪度 + ③ 配额台账 |

### 3.2 形态：为什么是 tab，不是第 6 页

1. **语义对**：tab = 同一条业务的两个视角；第 6 页 = 新的业务。碳账不是新业务，
   是台账业务的"正式口径"分支。
2. **边界不破**：`docs/43` 冻结的是「无登录 / 无权限 / 无上传页」，**不是**禁新增只读 tab；
   而"页面只读 `data/processed`"这条恰好要求先做适配器导出。
3. **有先例**：OBD 通道已用同样做法并入「云边端硬件监控」页，形态一致、审查一致。
4. **不改软著边界**：五页结构保持不变，导航不改、手册不改。

### 3.3 六块内容（页 / 组件 / 字段级）

**落点**：`app/main_views.py::render_ledger`（路由 `/ledger`）拆两个 tab：
「⚙️ 工程口径 E₀（主账）」= 现状整段不动；「📋 碳会计口径 A0–A6（审计轨）」= 新增。

**新增件**：

| 文件 | 作用 |
|---|---|
| `src/carbon_ledger_export.py` | 适配器：读 `carbon_ledger/` 工作簿 → 导出 7 张结果表 |
| `config/carbon_ledger_field_map.json` | 51 字段的就绪度映射（只描述就绪度，不含任何因子数值） |
| `app/components/carbon_ledger_panel.py` | 面板（六块内容 + 边界声明） |
| `app/services.py` | 只读层 7 个函数（30 s TTL） |
| `src/schema.py` | 注册 7 个结果文件名 |
| `tests/test_carbon_ledger.py` | 27 例（适配器 / 判定链 / 口径 / 只读守卫） |
| `tools/verify_carbon_ledger_tab.js` | tab 视觉与文案验收 |

**六块**：

| # | 块 | 关键字段 |
|---|---|---|
| ① | 账本状态条 | 账本状态 · 正式汇总 `NO_APPROVED_ROWS` · 口径 `WTW` · 因子状态 `proxy_pending_verification` · `12 行 simulated` · 「只读 · 不参与 28 条闸门 · 不回写 E₀」 |
| ② | **正式汇总资格判定链** | 9 项谓词逐条：通过/阻断计数 + 阻断主因（如 `simulated × 12`）；末行「12/12 行在第一道判定即被阻断」 |
| ③ | 配额台账 | 期初 1.0000 / 购入 0.2000 / 可用 1.2000 / 已用 2.4393 / 结余 0.0000 / **缺口 1.2393** + 原始字段折叠区 |
| ④ | 证据链索引 | 13 条；「凭证文件存在」= **适配器实时按文件系统判定**（0/13）；状态三态：未提供 3 / 已提供 1 / 空白 9 |
| ⑤ | 活动量 51 字段就绪度 | 工程侧 29 / OBD 5 / 发票 6 / 待财务 6 / 待外部 5 |
| ⑥ | 规则与自证 | 控制规则 14 / 基础用例 15 / 压力场景 19（19 PASS）/ 自检脚本**未随交付** + 规则卡原文 |

### 3.4 明确不做的事

| 不做 | 原因 |
|---|---|
| 审批按钮 / 任何写控件 | `Owner_Approval_Status` 只能由人在 Excel 里填；页面能写就等于造出第二真源 |
| 凭证上传 | `docs/43` V1.0 禁上传页 |
| 页面里写核算公式 | 项目铁律「前端只读不算」，AST 级测试守着 `app/services.py` |
| WTW 与 TTW 并排比大小 / 相减 / 做趋势对比 | 两边核算范围也不同（12 条合成趟次 vs 全网趟次），比出来的是伪差异 |
| 用「0 行」说成零排放 | 页面固定写「无合格正式行，不等于实际排放为零」 |

## 4. 技术实现

### 4.1 适配器

`python -m src.carbon_ledger_export`（`--no-write` 只打印摘要）

* 读 `carbon_ledger/a2|a4|a5` 的工作簿，**取工作簿已算好的缓存值**（`openpyxl data_only=True`）；
* **不重算**排放量、不重算汇总 —— 主账的 X/Y 列与各级 Summary 直接搬运；
* **不写**交付方任何文件（`tests` 里有 mtime 不变断言）；
* 唯一允许"算"的是**判定链拆解**：主账只存了合成判定 `Formal_Summary_Eligibility`，
  前端要说明"为什么 0 行"，就得把 `AP2` 的每个谓词单独求值 —— 属于复现已有公式的判据。

### 4.2 结果表（7 张，落 `data/processed/`）

| 文件 | 内容 |
|---|---|
| `carbon_ledger_trips.parquet` | 主账 42 列 + 9 个 `gate_*` 谓词列 + `gate_first_block` + `row_formal_approved`（12 行） |
| `carbon_ledger_evidence.parquet` | 证据索引 15 列 + `evidence_file_exists` / `evidence_file_resolved` / `is_row_level` / `status_bucket`（13 行） |
| `carbon_ledger_summary.json` | 状态条数据、月年汇总、正式汇总、口径分解与边界声明 |
| `carbon_ledger_gates.json` | 9 项判定链：计数、阻断主因、首阻分布、合成判定分布 |
| `carbon_ledger_quota.json` | 配额台账（数值 + 原始字段 + 台账说明） |
| `carbon_ledger_activity_readiness.json` | 51 字段就绪度与分类计数 |
| `carbon_ledger_rules.json` | 14 条控制规则 / 15 项用例 / 19 项压力场景 / 可行性自查 / 规则卡原文 |

### 4.3 只读层

`app/services.py` 新增 7 个函数 + `carbon_ledger_available()`，TTL **30 s**（与 OBD 轨一致）：
交付方更新工作簿 → 重跑适配器 → 页面自动跟上，不要求重启应用。

## 5. 口径纪律

### 5.1 两套口径

| | 碳会计轨 | 工程 E₀ |
|---|---|---|
| 口径 | **WTW 全生命周期**（尾管 + 上游） | **TTW 尾管燃烧** |
| 柴油因子 | 3.16 kgCO₂e/L | 2.63 kgCO₂/L |
| 单元 | 物理趟次 | 运单关联路段 |
| 门禁 | 人工审批 + 正式汇总资格 + 证据索引 | 28 条对拍闸门 |
| 状态 | 未冻结、未批准 | 已发布（run `20261027-152051-71d711d6`，28 PASS） |

3.16 = 2.63（`config/calc_factors.json` TTW）+ 0.53（WTT）—— 差 20.2% 是**核算边界差异，不是数据错误**。
结果表里**刻意不同时放两边的总量**（有测试守着）。

### 5.2 正式汇总资格的 9 个谓词（`Trip_Detail!AP2`）

`Data_Status=actual` ∧ `Simulated≠yes` ∧ `Factor_Status=factor_verified` ∧
`Validation_Status=PASS_FORMAL_PRECHECK` ∧ `Physical_Trip_Control=PASS_UNIQUE_PHYSICAL_TRIP` ∧
`Owner_Approval_Status=approved` ∧ `Evidence_ID≠""` ∧ `Run_ID≠""` ∧ `Source_Ledger_Row_No≠""`

> `docs/53` §4 记成 8 个，漏了 `Source_Ledger_Row_No` 非空 —— 本文档与实现按 9 个。

当前 12 行的实测判定：前 4 项与第 6 项**全部 12/12 阻断**，第 5、7、8、9 项全部通过；
12 行都在**第一道**判定即被阻断 → 正式汇总 0 行。
