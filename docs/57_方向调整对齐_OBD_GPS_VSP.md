### 2.2 不冲突，但**必须写清定位** ⚠️

**仓库里的 CO₂ 传感器不是车载测排放。**
`src/sensor.py` 的口径是 **空间环境浓度 → 超标碳排量 → 额外碳配额成本**：
`excess_kg = 浓度差 × 房间体积(m³) × 空气密度 × CO₂/空气摩尔质量比`，
阈值 1000 ppm，输入是**「监测空间体积 (m³)」**。

所以：

| | 老师否掉的 | 仓库里有的 | 结论 |
|---|---|---|---|
| 场景 | **车载** CO₂ 浓度测排放 | **仓储 / 办公场所**环境 CO₂ 监测 → 超标罚单 | **不是同一件事，不冲突** |

但答辩时一定会被问「不是说放弃 CO₂ 传感器了吗，怎么还有个 CO₂ 页」。
**必须在硬件监控页与 README 写一句定位**：
> 本页是**仓储 / 办公场所的环境 CO₂ 监测与碳资产管理**（超标 → 额外碳配额成本），
> **不是运输排放测量**；运输排放由 OBD+GPS 实测轨与 VSP 模型轨承担。

### 2.3 真正的缺口 🔴

| # | 缺口 | 说明 |
|---|---|---|
| G1 | **VSP 用的不是速度剖面** | 我们现在是 `门到门平均速度 → VSP 指数 → 平均排放率 × 总时长`（`SPEED_POLICY = "door_to_door"`）。**加速 / 减速 / 怠速的瞬态全部丢失** —— 而老师口径的 VSP 正是吃速度剖面的 |
| G2 | **VSP 曲线是 5 点代理插值** | `VSP_X = [0,1,2,3,4]`、`VSP_MULT = [0.82,0.92,1.00,1.1268,1.24]`、`VSP_VERSION = "VSP-PROXY-v1"` —— 版本名自己就写着 PROXY；论文/专利的正式参数表未落地 |
| G3 | **VSP 缺「排放标准」维度** | 现在的因子表维度是 `(车型类别, 载重) → g/km`；老师口径要求含**排放标准**（国三/国四/国六…） |
| G4 | **国网电力装备运输场景未落地** | 演示数据是普通货运；大件电力装备运输（重货、多装卸、低速、特种车型）没有对应演示场景与因子 |
| G5 | **硬件对接未启动** | `config/obd_gps_contract.json` 是给朱汝成对接用的，**应立即冻结并发给他**；目前还带演示默认值 |

> 🔴 **G1 + G3 恰好是 OBD 通道能补的**：OBD+GPS 给的是 **2 秒级真实速度剖面**（含怠速占比、巡航、峰值）
> —— 这正是 VSP 模型需要的输入。**两条线在这里合流**，而不是各做各的。

## 3. 三个问题的答复（2026-10-29 已定）

### Q1 · E₀ 主口径是否切到 VSP？—— **不切**，三轨分工写死

| 轨道 | 方法 | 地位 |
|---|---|---|
| **法定轨（发票）** | 发票油耗 × 因子 | **E₀ 主碳账**（不动） |
| **OBD+GPS 实测轨** | **碳平衡法（燃料守恒法）** —— OBD 只测油耗，碳由守恒系数推出 | 独立新证据链，**不进主账**，做**锚点** |
| **VSP 技术轨** | 速度/车型/载重估算 | **敏感性分析 + 对照验证**（给没有 OBD 的 12,167 趟兜底） |

**碳平衡法与 VSP 不是二选一，是互补：**

- 碳平衡法管「**实测那部分算得准**」（`config/obd_carbon_factors.json` + `src/obd_gps.py`，
  守恒推导值与权威因子偏差 0.628%，3% 容差内）；
- VSP 管「**没实测的全量能估、且估得能被验证**」——
  OBD 只能覆盖装了设备的试点车，主账 12,167 趟历史运单没有实测数据，只能靠 VSP 估算。

> **结论：E₀ 主口径不切。** 口径冻结（`docs/03`/`docs/08`）与 28 条闸门对拍值一律不动；
> 双轨并列反而是答辩加分项（「双轨 + 对拍」比单轨更硬）。

### Q2 · OBD 与 VSP 怎么合流？—— **做对照验证**（已落地第一版）

**判据（老师原话，登记为验收标准）**：

> 「你测的和这些估的能不能对得上？对不上，那估的可能就不用了。」

**已实现**：`src/obd_vsp_crosscheck.py`（独立轨道，不改任何既有口径）

```
实测轨  碳平衡法（守恒法）        ← obd_points.parquet（既有结果，不重算）
模型轨  VSP 速度剖面积分          ← 逐点速度 → VSP → 排放率 → 时间积分
        VSP 平均速度法（对照）     ← 工程侧现行口径，作为 G1 的量化基准
输出    逐趟 × 载重档偏差表 + 逐点 ER 对照 + 汇总结论
```

**当前演示数据下的结果**：

| 指标 | 值 |
|---|---|
| 实测（碳平衡法） | 136.8389 kgCO₂ |
| 模型（速度剖面积分） | 141.9651 kgCO₂ → **偏差 +3.75%** |
| 模型（平均速度法） | 139.8086 kgCO₂ → 偏差 +2.17% |
| **速度剖面比平均速度法高** | **+1.54%** ← 这就是 **G1 的量化值**（丢掉瞬态的代价） |
| 判定 | ±15% 容差内 → **「对得上」** |

**但载重是扫描假设**：演示序列不填 `load_kg`，所以模型因子按载重锚点档扫描、取偏差最小的一档，
输出里标 `load_basis = scan` 并明确写「**扫描得到的最佳档不构成「可用于兜底」的结论**」。
真实设备上报 `load_kg` 后自动切到 `measured`，这条结论才有最终效力。

> **顺带修掉一个真 bug**：演示生成器用未缩放的原始速度累计里程，而速度/油耗都乘了 `scale`
> —— 轻卡里程虚高 **61.3%**、碳强度被低估 38%（646 vs 1042 g/km）。
> 不修它，对拍会得出完全错误的结论。已加两条回归断言（`tests/test_obd_vsp_crosscheck.py`）。

### Q3 · 硬件对接何时启动？—— **暂不推进**

契约（`config/obd_gps_contract.json`，27 例测试）保持可用状态，**不发**；
硬件型号、协议与油耗字段类型确认后再启动，避免按旧 PPT 思路返工。
**遗留**：真实载重接入是 Q2 结论转正的前置条件，需要硬件侧配合上报 `load_kg`。
