### 2.2 不冲突，但**必须写清定位** ⚠️

**仓库里的 CO₂ 传感器不是车载测排放。**
`src/sensor.py` 的口径是 **空间环境浓度 → 超标碳排量 → 额外碳配额成本**：
`excess_kg = 浓度差 × 房间体积(m³) × 空气密度 × CO₂/空气摩尔质量比`，
阈值 1000 ppm，输入是**「监测空间体积 (m³)」**。

所以：

| | 老师否掉的 | 仓库里有的 | 结论 |
|---|---|---|---|
| 场景 | **车载** CO₂ 浓度测排放 | **仓储 / 办公场所**环境 CO₂ 监测 → 超标罚单 | **不是同一件事，不冲突** |

但答辩时一定会被问「不是说放弃 CO₂ 传感器了吗，怎么还有个 CO₂ 页」。
**必须在硬件监控页与 README 写一句定位**：
> 本页是**仓储 / 办公场所的环境 CO₂ 监测与碳资产管理**（超标 → 额外碳配额成本），
> **不是运输排放测量**；运输排放由 OBD+GPS 实测轨与 VSP 模型轨承担。

### 2.3 真正的缺口 🔴

| # | 缺口 | 说明 |
|---|---|---|
| G1 | **VSP 用的不是速度剖面** | 我们现在是 `门到门平均速度 → VSP 指数 → 平均排放率 × 总时长`（`SPEED_POLICY = "door_to_door"`）。**加速 / 减速 / 怠速的瞬态全部丢失** —— 而老师口径的 VSP 正是吃速度剖面的 |
| G2 | **VSP 曲线是 5 点代理插值** | `VSP_X = [0,1,2,3,4]`、`VSP_MULT = [0.82,0.92,1.00,1.1268,1.24]`、`VSP_VERSION = "VSP-PROXY-v1"` —— 版本名自己就写着 PROXY；论文/专利的正式参数表未落地 |
| G3 | **VSP 缺「排放标准」维度** | 现在的因子表维度是 `(车型类别, 载重) → g/km`；老师口径要求含**排放标准**（国三/国四/国六…） |
| G4 | **国网电力装备运输场景未落地** | 演示数据是普通货运；大件电力装备运输（重货、多装卸、低速、特种车型）没有对应演示场景与因子 |
| G5 | **硬件对接未启动** | `config/obd_gps_contract.json` 是给朱汝成对接用的，**应立即冻结并发给他**；目前还带演示默认值 |

> 🔴 **G1 + G3 恰好是 OBD 通道能补的**：OBD+GPS 给的是 **2 秒级真实速度剖面**（含怠速占比、巡航、峰值）
> —— 这正是 VSP 模型需要的输入。**两条线在这里合流**，而不是各做各的。

## 3. 三个必须拍板的问题

### Q1 · 工程侧 E₀ 主口径是否切到 VSP？

**现状**：E₀ 主账 = **法定物理轨（TTW 燃料法）2,258.438 t**；VSP 轨 2,324.654 t 是**技术轨**。
（`docs/41` §1 明确写「VSP 是技术轨/敏感性分析，不是主碳账」。）

**老师口径**把 VSP 定为「排放计算模型」。两种理解：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（建议）不切主口径** | 双轨保留；把 VSP 表述改为「**运输排放的核心计算模型**」，法定轨作为**合规口径**并列 | 口径冻结与 28 条闸门对拍值**不动**；答辩时用「双轨 + 对拍」讲，比单轨更硬 |
| B 切主口径 | E₀ 主账改用 VSP 轨 | **破口径冻结**：28 条闸门的对拍目标值全部要重算，`kpi.json` / `gate_report.json` / 软著材料 / 报告数字全变；且 VSP 曲线是 PROXY（G2），主口径不该挂在代理参数上 |

**建议 A**：老师要的是"VSP 是模型"，我们要的是"VSP 是模型 **且** 双轨可对拍"。
口径冻结（`docs/03`/`docs/08`）+ 28 条闸门是**比赛复现性与软著冻结物**的基础，
现在切，收益远小于代价。

### Q2 · OBD 速度剖面是否驱动 VSP 模型？

**建议：是，做成第四条证据链。**

```
现状：  平均速度 → VSP指数 → 平均ER × 总时长          （丢瞬态）
应做：  逐点速度剖面 → 逐点VSP/ER → 时间积分          （保留怠速/加速/减速）
        ↑ OBD+GPS 的 2 秒级速度、里程、车型、载重 —— 全部现成
```

这样得到三样东西：
1. **模型轨**：用真实速度剖面驱动的 VSP 结果（补 G1）；
2. **实测轨**：OBD 守恒法直接算的碳排（已有）；
3. **交叉验证**：模型 vs 实测的偏差 —— **这正是 OBD 通道当初留的接口，一直没用上**。

> ⚠️ 这条会让 OBD 通道从「第三条证据链」升级为「**模型与实测的交汇点**」，
> 答辩分量明显不同。代价：需要把 `src/carbon_model.py` 的 VSP 计算改成**可接收逐点速度**，
> 并定义速度剖面积分与平均速度法的口径差异（不能混算）。

### Q3 · 硬件对接现在启动还是等？

**建议：立即冻结契约并发给朱汝成。**
`config/obd_gps_contract.json` 是设备端与后端共用的一份（字段、别名、质控、接入方式），
已经过 27 例测试；**硬件若现在按旧 PPT 思路做，返工概率极高**。
建议本周内：冻结契约 → 发给朱汝成 → 确认 OBD 型号（协议 / 帧 ID / 油耗字段是瞬时还是累计）
→ 我方按真实字段调整别名表（`build_alias_map` 已兼容别名，扩字段成本低）。
