## 1. 一句话

把「路段级功率-速度排放因子」+「k-means 工况聚类」+「向量值 TD(λ)」+「Double Q 策略选择」+「模型残差修正」+「15 分钟速度预报」+「车队配额压力」拼成一条能实时重估到达时间、能中途重规划、能把实测数据吸回来的决策链。

## 3. 路段级排放因子（用户给定公式）

### 3.1 公式与量纲

```
EF(g/km) = [A + a·(kW_t/v) + B + b·kW_t + (C + c·kW_t)·v + (D + d·kW_t)·v²] · k_{i,j}
```

| 符号 | 含义 | 单位 |
|---|---|---|
| `v` | 该路段**平均**车速（瞬时波动已被 `kW_t` 吸收） | km/h |
| `kW_t` | 路段平均发动机功率：① OBD 实测；② 功率模型回退 | kW |
| `A..D` | 与功率无关的速度曲线项 | g/km |
| `a..d` | 功率耦合项；`a` 的量纲是 **g CO₂/kWh 机械功** | 见下 |
| `k_{i,j}` | 道路等级 `i` × 载重分箱 `j` 的修正系数 | 无量纲 |

**为什么是这组基函数**：巡航时 `kW ≈ F·v`，于是 `a·kW/v = a·F`，这一项直接等于「阻力 × 碳强度」，是燃料守恒法的物理主干；`kW_aux/v` 给出低速段上扬的 1/v 形状；`v²`、`kW·v²` 描述高速风阻段。`A..D` 吸收功率模型没覆盖的道路条件偏差。

**A 与 B 共线**（都是常数项），同时拟合不可辨识。默认 `B = 0`，标定时常数项全部并进 `A`；`calibrate_coefficients()` 显式拒绝同时拟合 A、B。

### 3.2 功率从哪来

```
P_wheel = (m·g·C_rr + ½ρC_dA·v² + m·g·grade + m·a)·v
P_eng   = P_wheel / η + P_aux，且 P_eng ≥ idle_kw
```

- `m = 整备质量 + 载重`，`η = 0.88~0.90`，`C_dA` 分车型给；
- **怠速下界 `idle_kw`**：没有它，1% 下坡在 30 km/h 就把滚阻抵消，重卡被算成 76 g/km（滑行工况），违背实测。轻 4 / 中 8 / 重 12 kW；
- **OBD 通道**用 ISO 15031 的 `Load_pct`（当前扭矩占最大扭矩比例）：`P = Load×T_max×ω/1000 + aux`；`SegmentCostModel.evaluate(..., power_kw=...)` 直接吃实测功率。

### 3.3 系数（占位标定，不是 PEMS）

`tools/rl_fit_emission.py`：用「燃料守恒 + 功率模型」在 15–90 km/h × 三档载重生成目标曲线（叠加速度相关起停惩罚），再把既有因子表 50 km/h 锚点加权并入，最小二乘拟合。

| 车型 | A | a | C | D | R² | 50 km/h 锚点偏差 |
|---|---|---|---|---|---|---|
| 轻型 4.5 t | 388.58 | 803.57 | −9.36 | 0.0549 | 0.954 | −14.3%（对 394.56） |
| 中型 12 t | 488.82 | 895.00 | −17.57 | 0.1240 | 0.977 | +2.6%（对 544.75） |
| 重型 30 t | 592.21 | 870.89 | −20.08 | 0.1401 | 0.977 | +0.5%（对 1055.95） |

`b/c/d` 默认 0：物理模型假设功率与速度无交互，这三项必须有 PEMS 数据（不同载重 × 不同速度）才能辨识。测试守住「重型 30 t / 50 km/h 与既有因子表差 < 15%」。

### 3.4 `k_{i,j}`：k-means 载重分箱 + 偏差中位数标定

- 载重按 k-means 中心切段，训练与推理共用边界（`config` 的 `k_ij.load_bins_edges`）；
- 每个（道路等级, 载重箱）取「实测/预测」比值**中位数**，与 docs/45 §5 的路段系数同口径；样本不足回退 1.0 并在 `fallback_groups` 点名；
- 当前表是占位假设，接 OBD 后跑 `clustering.calibrate_k_table()` 重标。

## 4. 为什么拆成「预测层 + 决策层」

| 层 | 学什么 | 算法 | 为什么不能合并 |
|---|---|---|---|
| 预测层 | `V(s) = (剩余时间, 剩余碳, 剩余费用)`，向量值 | TD(λ)，γ=1 | ETA/碳预测要对三个目标同时给数，不该先定权重；折现会让 ETA 系统性偏低 |
| 决策层 | `Q(s, 策略)`：当前工况下用哪套运营权重 | Double Q + 蒙特卡洛回报 | 权重随工况/配额变，需要离散、可解释、可迁移的动作 |

状态抽象：`cluster(k-means) × 进度档 × 时段档` → 默认 `8 × 5 × 8 = 320` 个 TD 状态；Q 用 `cluster × 时段 (× 压力档)` = `64`（启用配额时 `256`）× 4 个动作。

### 4.1 为什么路由用 Dijkstra 而不是让 Q 直接选边

路网一换，Q 表就废；Dijkstra 立刻可用。所以让 Q 只学「权重」这个低维、可迁移、可解释的量。

代价要讲清楚：在这张演示网上，每个时段都有占优选项，而这个占优关系模型自己就算得出来，所以学习策略与最强静态基线**并列**（§11、§15.3）。学习真正赢的地方在预测层。

## 5. MDP 形式化

| 要素 | 定义 |
|---|---|
| 状态 `s` | `(工况簇, 进度档, 时段档)`；Q 另加「配额压力档」 |
| 动作 `a` | ① 决策层：4 套权重预设之一（出发时选一次，全程不变）；② 执行层：Dijkstra 在此权重下取第一段 |
| 转移 | 交通外生演化（与「我们怎么走」无关）+ 路段行程时间推进时钟 |
| 奖励 | 决策层：`−U(整单实际)`；预测层：每段实际 `(时间, 碳, 费用)` |
| 终止 | 到达终点，或步数上限（`max_steps=120`） |
| 约束 | 禁行段屏蔽、不可达剪枝、重规划迟滞（8%）+ 冷却（3 min）、策略切换惩罚（0.02） |

`U = 0.45·T/T_ref + 0.35·C/C_ref + 0.20·M/M_ref + 0.02×重规划次数`（启用配额时权重随压力变，见 §15.1）。

**为什么奖励用整单蒙特卡洛回报**：单段奖励与「这段路多长」混淆（1.6 km 高速段天然比 0.75 km 路口段贵），会把 Q 教成「选贵的那条」。

**为什么 γ=1（预测层）**：折现会让「剩余时间」被乘上 γ^k 系统性偏低（γ=0.95、10 段低估约 30%）。折扣只在决策层有意义（γ_q=0.9）。

**为什么 Double Q**：取 max 的那一步带噪声（拥堵数据抖动），单 Q 会系统性高估。

## 6. k-means 的三个明确用途

纯 numpy 实现（k-means++ + 8 次重启），不引 sklearn：为 120 行算法加 30 MB 重依赖不划算，离线打包也变重。

| 用途 | 输入 | 输出 | 消费方 |
|---|---|---|---|
| 状态抽象 | `[上游拥堵, 下游平均拥堵, 载重, 下游平均坡度, 时段]` | 8 个工况簇 | TD / Q 的状态下标 |
| 载重分箱 | 历史载重样本 | 3 个边界 → 4 个箱 | `k_{i,j}` 的下标 `j` |
| `k` 标定 | 分组后的「实测/预测」比值 | 修正系数表 | `emission.lookup_k_factor` |

冷启动时用特征空间均匀覆盖拟合中心；有轨迹后换 `collect_state_samples` 的随机游走采样。

## 7. 在线更新怎么跑（实时性）

```
外部数据（拥堵快照 / OBD 油耗·转速·负荷 / 载重 / 坡度）
        │
        ├─ 决策：Q 选策略 → 修正边权 → Dijkstra → 迟滞判定 → 建议（action + 逐段明细 + ETA）
        │
        └─ 反馈：走完一段 → TD 更新（V + 资格迹）→ 整单结束 → Q 更新（−U）+ 预测器打分
```

- **逐段更新**：TD(λ) 的资格迹 `e ← γλe + 1`，一次回溯更新整条轨迹；
- **整单更新**：Q 用 `−U(整单)` 更新一次，同时给「模型 / TD / 预报」三路 ETA 打分（EWMA α=0.2），谁准听谁；
- **持久化**：`save_policy()` 落 `outputs/rl/policy.json`（量化器 + V + Q + 修正层 + 预测器误差 + 残差样本），服务重启 `load_policy()` 直接接上。

**重规划迟滞**：新方案必须比在跑的方案便宜 8% 以上，且距上次换方案 ≥3 分钟才换。没有它，路况微抖动会让方案每段都改；更糟的是逐段换目标会把车开成「先南下再北上」的环路（实测 19:00 那单多跑 5 分钟）。

## 8. 仿真场景（外生交通）

| 模块 | 做法 | 理由 |
|---|---|---|
| 时段需求 | 早晚高峰高斯峰叠基线 | 阶梯函数会让速度跳变 |
| 速度-流量 | BPR：`v = v_free / (1 + 0.15·(q/c)^4)` | 交通工程标准形式 |
| 事故 | 全网 1.5 起/小时（雨天 ×1.9），持续 10–40 min，等效能力下降 | 真实事故是能力下降不是封路 |
| 溢出 | 下游 v/c > 0.9 时压低上游，只做一轮、先算后写 | 边算边写会沿路网自乘，峰值锁死 4 km/h |
| 天气 | 雨/雾/雪 → 降速 + 提事故率 | 前端可切，答辩可演 |
| 路网 | 4×4 方格（50 km/h）+ 一条对角高架（85 km/h，5.5 km / 1.22 倍距离） | 平峰只快 1 分钟、高峰快 3–4 分钟 |

**为什么交通必须外生**：若路况受「我们这辆车」影响，事后最优不可算，也就没有下界可比。货运单车完全成立。

## 9. 接口

### 9.1 配置（`config/rl_policy.json`，唯一超参来源）

`emission`（系数/单位/燃料）、`vehicles`、`k_ij`、`clustering`、`rl`、`strategies`、`operation_weights`、`correction`（残差修正）、`eta`（共形 P90）、`sim`（仿真偏差）、`quota`（配额）、`forecast`（预报）、`traffic`、`economics`、`scenarios`、`evaluation`。改值必须 bump `version`。

### 9.2 前端 payload（`RecommendationService.recommend`）

```
{ action, strategy{sid,label,weights}, strategy_confidence, q_values,
  plan{path,time_min,carbon_kg,cost_yuan,rows[]},
  eta{eta_min,eta_p90_min,eta_p90_source,model_time_min,learned_time_min,forecast_time_min,confidence},
  segment_detail[每段: km/h, kW, g/km, kg, 拥堵标签], reasons[], state{...} }
```

字段顺序与 `tools/rl_demo.py` 的打印稿一致，前端照抄即可。

### 9.3 实时数据接入（`src/rl/live.py`）

```python
trip = LiveTrip(network, policy, TripRequest("G00", "G33", load_t=18))
trip.traffic(payload, minute=480.5)          # ① 拥堵快照 → 时间线
advice = trip.decide()                        # ② 策略/路径/ETA/逐段明细
trip.report(advice["action"], power_kw=obd)   # ③ 走完一段：OBD 功率 + 更新 TD/Q/修正层
```

payload：`{"segments": [{"sid": "E_G00_G01", "speed_kmh": 18.2, "vc_ratio": 1.1}]}`。三条纪律：不编数据（缺字段进 `rejected`）、增量合并（未推路段继承最近帧）、三档计数（accepted/ignored/rejected）。`TrafficTimeline` 支持稀疏帧，`at()` 自动退到最近一帧，推送间隔不必是 1 分钟。

### 9.4 P90 是输出列，不是学习状态

| 旋钮 | 位置 | 作用 |
|---|---|---|
| `eta.p90_quantile` | config | 分位数（默认 0.90） |
| `eta.min_residuals` | config | 残差样本门槛（默认 40） |
| `eta.residual_window` | config | 滚动残差窗口（默认 400） |

运行时也可 `policy.set_eta_interval(quantile=0.8)`：不重训、不动 `policy.json`、不碰 V/Q/修正层（有测试守着）。config 显式写了就以 config 为准。

|---|---|---|---|---|---|
| **学习策略** | **7.352** | **4.586** | **11.344** | **1.451** | **1.0826** |
| 时间优先（静态） | 7.352 | 4.586 | 11.344 | 1.451 | 1.0826 |
| 低碳优先（静态） | 8.137 | 4.347 | 10.752 | 1.376 | 1.1247 |
| 专家规则 | 7.352 | 4.586 | 11.344 | 1.451 | 1.0826 |

- U 只用来看相对排序，不跨版本比绝对值（v1.2 注入了模型偏差，绝对时间变长）。

## 12. 已知限制（必须写进答辩口径）

1. **系数是占位标定**：由燃料守恒 + 功率模型拟合，不是 PEMS 实测。锚点偏差最大 −14.3%（轻型）。接实测后跑 `tools/rl_fit_emission.py` 重标并 bump 版本；
2. **演示路网是合成的**（4×4 + 一条对角高架），不是真实城市。接高德/OSM 只需替换 `RoadNetwork.from_spec`，算法不动；
3. **本路网上学习策略与最强静态基线并列**：每个时段都有占优选项，模型自己就能找到；修正层与配额层都改变不了路线（§15.3 给根因）。学习层的价值在预测精度（§11.2）与机制完备性，不在「打败静态权重」；
4. **P90 用共形残差分位数**（滚动 400 条），仿真覆盖率 0.97–1.00；真实数据分布不同，上线前要重算 `min_residuals` 与窗口；
5. **配额只到「车队账本 + 单车决策」**：车辆之间的配额分配未设计；压力→权重是经验函数，不是从企业真实规则反推；BPR 没有排队论级溢出物理；
6. **修正层只验证了时间偏差**：碳偏差代码路径同构且有单测，但默认仿真没注入碳偏差；
7. **15 分钟预报没接路由**：技能 +85%，但本网单程短于预见期，接进去选路不变（§15.2）；
8. **前端未接线**：payload、`LiveTrip`、打印稿已就绪，Streamlit 页面与 HTTP 端点待接。

## 14. v1.1 优化记录（2026-11-06）：按问题改，不按感觉改

### 14.1 学习只改显示，模型偏差没人管

**现象**：`learned` 与 `static_time` 完全并列；模型有偏差时 ETA 误差 2.2 min，而路由完全不知道。

**方案**：`ResidualCorrector`——按（道路等级 × 时段）在线学「实际/模型」比值：

```
ratio ← ratio + α_eff·(actual/model − ratio)     α_eff = max(0.25, 1/(n+1))
n ≥ 3 才生效，比值夹在 [0.5, 2.5]
```

回灌 `SegmentCostModel`，Dijkstra 边权变成 `t_model × ratio`，ETA 的模型项也变准。分工：**Q 管「偏向哪个目标」，修正层管「模型哪里算错了」**。

**证据**：§11.2。ETA 0.364 → 0.0369 min；4 个注入比值逐格复现；预测器权重自动从「信 TD」倒向「信修正后的模型」。

**没解决**：路线选择仍与静态基线并列（根因见 §15.3）。

### 14.2 P90 是拍脑袋的 2.5×MAE

**现象**：覆盖率只有 0.45–0.70。

**方案**：共形预测——滚动 400 条 `实际剩余 − 融合预测` 残差，P90 取 90% 分位；样本 <40 退回 2.5×MAE，字段 `eta_p90_source` 标明来源。

**证据**：覆盖率 0.967 / 1.000。

### 14.3 重规划「抽风」（5 段报 4 次）

**根因**（真 bug）：`_remaining_of_last_plan` 用「方案路径前缀是否等于 `env.path`」判断有效性，但方案记的是**从决策节点出发的剩余段**，中途重排后永远对不上 → 每段都算重规划，迟滞形同虚设。

**方案**：游标 `_plan_offset` 记录方案生成时的 `len(env.path)`；再叠 3 分钟冷却 + 8% 阈值。

**证据**：`replans/单` 4.17 → 1.00。

|---|---|---|
| 接 PEMS 实测重标系数 | 没有数据 | 拿到实测后跑 `tools/rl_fit_emission.py` |

| 真正的交通预测（未来 15 min） | 需要上游流量/历史断面 | v1.2 已补物理外推，见 §15.2 |

## 15. v1.2 优化记录（2026-11-06）：配额 + 15 分钟预报

针对上一轮列的 3（学习对选路无增量）、5（多车配额）、6（交通预测）三条。

### 15.1 车队碳配额：让「运营目标」随压力变

固定权重下「该走哪条路」由路况决定，Q 与最强静态基线并列——**不是算法退化，是目标不变**。真实车队的约束会变：月初配额宽松，月末见底，同样的碳按越来越高的影子价买单。

```python
quota = FleetQuota(budget_kg=60, trips_total=18)
pressure = quota.pressure()      # ref / allowance，>1 更紧，夹在 [0.2, 3.0]
weights  = quota.weights()       # 碳↑、时间↓、费用↓，归一化
quota.consume(carbon_kg)
```

纪律：**权重只改「裁判」（U），不改路由器**。路由器仍只看到 4 套固定权重，Q 必须自己学会「这个压力档该挑哪套」。

Q 的状态因此拆两半：预测层（TD）仍 `8×5×8=320`，**不看配额**（ETA 不该随配额变）；决策层（Q）`8×8×压力档`，启用配额时压力档 = 4 → `256×4`。训练用**域随机化**：压力在 `[0.90, 1.05, 1.25, 1.60]` 轮转，否则模型只见过「配额紧」这一种世界。

**日级评估**（`--quota-budget 60`，18 单，同一预算、各自消耗）：

| 策略 | 碳 kg | 费用 元 | 运营口径 U | 峰值压力 |
|---|---|---|---|---|
| 学习策略 | 82.55 | 204.18 | 19.001 | 3.00 |
| 时间优先（固定） | 82.55 | 204.18 | 19.001 | 3.00 |
| 低碳优先（固定） | 78.25 | 193.53 | 19.633 | 3.00 |

**能看到的**：策略随压力切换——P≈1.0 选「时间」，P≈1.3 选「抗堵」，P≥1.8 转「低碳」，末期回「均衡」。
**没看到的**：U 差 0.00%。原因是**四套预设在本网多数出发时刻给出同一条路**——每个时段都有占优选项，Pareto 前沿退化成一个点。配额这层因此只证明「机制通」，没证明「收益大」。根因与 §11 第 3 条同源。

### 15.2 15 分钟速度预报：从「当前快照」到「到达时多快」

窗口只有 10–20 分钟，可靠信息只有三条：当前速度、需求曲线走向、事故剩余时间。用**物理外推**：

```
vc_now  = ((v_free_eff / v_now − 1) / 0.15) ** 0.25      # BPR 反解
vc_pred = vc_now · demand(t+Δ)/demand(t) · 事故衰减
v_pred  = v_free_eff / (1 + 0.15 · vc_pred⁴)              # BPR 正解
```

事故分段：预测到达时未清 → 保持当前速度；已清 → 按 0.65 残余系数恢复（排队消散是假设）。

**实测技能**（对仿真真值，1392 个「路段×时刻」样本）：

| 预见期 | 本模型 MAE | 保持当前速度 MAE | 增益 |
|---|---|---|---|
| 5 min | 0.158 km/h | 0.884 | **+82%** |
| 10 min | 0.268 | 1.663 | **+84%** |
| 15 min | 0.376 | 2.454 | **+85%** |
| 30 min | 0.575 | 4.681 | **+88%** |

接进 ETA 作**第三路预测**（模型 / TD / 预报），权重仍是 `1/MAE²`：准就自动加权、不准就自动出局。

**为什么没接路由**：把预报塞进时间依赖 Dijkstra，六个出发时刻的选路**完全相同**——本网单程 7–10 分钟，短于 15 分钟预见期，预报还没发挥作用车就到了。不做「为了用上而用上」的接线。

### 15.3 这一轮没解决的（诚实记录）

| 问题 | 状态 |
|---|---|
| 3 学习对选路无增量 | **仍未解决**。机制（时变目标）有了，但动作空间退化：四套预设常同路，U 差 0.00% |
| 5 多车协同 | 部分实现：车队配额账本 + 压力感知决策；车辆之间怎么分配配额仍未做 |
| 6 交通预测 | 已实现（速度技能 +85%），ETA 已用；路由未用（实测无效） |

根因收敛到一句话：**动作是「权重」，而权重在这张网上不改变路径**。真正的修法是让动作变成「候选路线」（Q 直接对 K 条候选排序，用实测 U 更新），而不是让 Q 调权重再由模型选路。这是 v1.3 的方向，代价是候选集生成与冷启动，不放进这一版。

## 16. v1.3 真实数据与真实路网（2026-11-06）

v1.3 按上一节的方向走：**动作从「权重」改成「四条高德候选路线」**，Q 直接对候选排序。

- 输入：287 个高德缓存 OD、4,014 趟历史；速度 5 档 × 载重 4 带的历史 EF 画像（TTW 2.63 kgCO₂/L）。
- 路网：每条高德策略建一条平行链，段长按该策略真实里程等分；四策略共享主路线 polyline，差异在里程/时长/收费。
- 训练：287 OD × 4 策略 × 30 epochs = 34,440 次离线全动作更新；64 个 Q 状态，访问 32 个。
- 结果：287 个 OD 全部由 Q 给出选择、0 次回退；选中路线 S0 248 / S4 26 / S1 9 / S6 4。
- 入口：路线页 “Q-learning 真实路网” Tab；策略文件 `config/rl_policy_real.json`。
- 细节、默认案例与边界：`docs/61_真实路网Q学习演示.md`。

这一版仍不改变「合成网 4×4 + 900 单」那套 v1.2 实验的结论；两套策略文件分开保存，页面优先加载真实策略。
