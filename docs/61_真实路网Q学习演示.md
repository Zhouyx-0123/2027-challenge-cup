## 1. 一句话结论

把 12,167 趟京东历史趟先聚成 K-means 3 簇，再把“簇 × 4 载重带 → 里程加权 EF”接到 287 个高德缓存 OD 上；每个 OD 用高德四种策略的真实里程/时长/收费构造四条候选链，Q 表在真实 OD 上离线拟合，直接对四个策略排序。演示不写主碳账、不改 E₀、不进 28 项闸门。

## 4. 真实路网怎么搭

每条高德候选路线建一条平行链：

```
AMAP_ORIGIN → AMAP-S0-N00 → … → AMAP-S0-Nxx → AMAP_DEST
             AMAP-S1-N00 → … → AMAP-S1-Nxx → AMAP_DEST
             AMAP-S4-… / AMAP-S6-…
```

- 段数 `max(6, min(40, round(最短里程/4)))`，不超过 polyline 点数减 1。
- 每段长度 = 该策略 `distance_km × 1000 / 段数`；四策略按各自里程等分。
- 段速度 = 整条路线 `distance_km / (duration_min/60)`；不是逐段实测。
- 道路等级由整条均速推：≥65 → 高速类，≥45 → 主干，≥25 → 次干，否则支路；只影响自由流速度与容量，不改变碳。
- 收费按段数等分；坡度统一 0。
- 几何：四策略共用该 OD 的高德主路线 polyline。**高德四种策略的真实差异在里程/时长/收费，不在几何**；页面已明确标注。

### 4.1 路线怎么映射到簇

Q 的决策单位是“一条候选路线”，不是“一个路段”。建网后对四条候选路线分别算：

```
x = [avg_speed_kmh, log1p(distance_km), load_t]
z = (x - scaling.center) / scaling.scale
cluster_id = argmin ||z - centers_scaled||
```

287 个 OD 的 1,240 条候选路线分类为 C0 310 / C1 500 / C2 430；只有 11 / 310 个 OD 的四策略会跨簇，绝大多数 OD 四条策略同簇。**这是路线级代理映射，不是逐段聚类**；页面和本文都按这个口径写。

## 5. 碳与费用模型

`HistoricalCostModel` 与合成网 `SegmentCostModel` 同接口：

```
time_min = length_km / speed_kmh × 60
cluster  = route_clusters[route_id]        # AMAP-S6-N00 → AMAP-S6
ef_g_km  = profile.cell(speed, load, cluster_id)
           # 簇×载重 n≥30 用簇规则；否则回退 5 档×4 载重带
carbon   = ef_g_km × length_km / 1000
fuel_l   = carbon / 2.63                    # TTW，与 E₀ 同口径
cost     = toll + fuel_l × 7.5 + carbon/1000 × 100
```

- 柴油因子 2.63 kgCO₂/L 是 TTW 主账口径；Q 模块原来的 3.16 是 WTW，两者不能相加或直接对比。
- 碳价默认 100 元/t，油价 7.5 元/L，只影响演示费用，不写主账。
- 运营成本 `operation_cost` 是相对“高德策略 0 参考路线”的归一化综合成本，不是元；策略 0 恒为 1.0。
- 结果里 `carbon_rule` 明确写 `kmeans_cluster_load` 或 `speed_load`；每段带 `rule_cell`（如 `C1/10-20`）或 `cluster_fallback=True`。

## 6. Q 表怎么来

`src/rl/real_policy.py`：

1. 对 287 个 OD 各建一次真实路网，取 `TripEnv.state_features()` = [上游拥堵, 下游平均拥堵, 载重, 平均坡度, 小时]。
2. 用全部状态样本拟合 `StateQuantizer`（8 簇，64 状态）。
3. 每个 OD 先算四条候选路线的簇，再用簇规则算 `[time, carbon, cost]` 与归一化运营成本。
4. 离线全动作更新：`q.update(state, action, -operation_cost, terminal=True)`；30 epochs。
5. 保存 `config/rl_policy_real.json`（policy + `real_data` 审计块）。

训练审计：

|---|---:|
| OD 数 | 287 |
| 动作数 | 4 |
| epochs | 30 |
| 更新次数 | 34,440 |
| Q 状态数 | 64 |
| 实际访问状态 | 32 |
| 最优动作计数 | time 11 / carbon 7 / balanced 11 / smooth 3 |
| 平均 Q | time −0.986667 / carbon −0.988589 / balanced −0.984603 / smooth −0.985130 |

这是 **contextual bandit 式的离线全动作评估**，不是让车在真实路网上随机探索，也不是逐段在线学习。页面按这个口径写。

## 7. 求解与兜底

`solve_real_route()` 对四策略逐一 Dijkstra，得到时间/碳/费用；Q 策略再选一次。下面任一条件触发回退枚举最优：

- Q 不可行或没有有效 Q 值；
- 置信度 < 0.05；
- Q 选择比枚举最优贵 > 10%。

全 287 OD 实测：`selected_is_q=287`，`fallback=0`，`selected route = best route` 287；选中路线分布 S0 247、S4 26、S1 10、S6 4；不是策略 0 的 OD 共 40 个。选中路线的簇分布：短途轻载 66、中距中载 118、长途重载 103。

## 8. 演示默认案例：镇江句容 → 南京奥南

25 趟历史、合计 1,063 km、载重中位 12 t、速度中位 43.0 km/h、出发中位 05:54（354 min）。四条候选都落在 C1 中距中载 / 10–20 t，规则格 `C1/10-20`，EF = 735.127 g/km。

| 策略 | 路线 | 里程 km | 时长 min | 碳 kg | 费用 元 | 运营成本 | 标记 |
|---|---|---:|---:|---:|---:|---:|---|
| 时间优先 | AMAP-S1 | 47.058 | 62.57 | 34.593 | 102.108 | 0.997497 | |
| 低碳优先 | AMAP-S6 | 45.298 | 65.35 | 33.297 | 98.283 | 0.996773 | 枚举最优 |
| 均衡 | AMAP-S6 | 45.298 | 65.35 | 33.297 | 98.283 | 0.996773 | |
| 抗堵稳健 | AMAP-S6 | 45.298 | 65.35 | 33.297 | 98.283 | 0.996773 | Q 选中 |

Q 值：time −0.999907、carbon −1.007094、balanced −1.001875、smooth −0.999886；置信度 1.000。Q 选中 S6，和枚举最优同路线，因此显示“Q 选择即枚举最优”。

这个案例说明两件事：一是时间优先会为了 2.6 min 多走 1.76 km、多排 1.30 kg 碳；二是 Q 表能区分“同一路线、不同策略标签”的细微差别。四条策略同簇，说明这次选择主要由时间/费用驱动，而不是簇 EF 差异。

## 9. 页面怎么用

1. 路线页 → “Q-learning 真实路网” Tab。
2. 顶部新增“上游碳规则 · K-means 3 簇”表：簇画像、中心、EF、趟数、碳占比；展开可看簇 × 载重带 EF 与样本数。
3. OD 默认选上述案例；可勾“只看多路线 OD”收窄到 228 个里程分叉的 OD。
4. 调载重、出发时刻、碳价，点“运行 Q 策略求解”。
5. 看五个 KPI（碳排脚注写 K-means 簇×载重 EF / 回退）、Q 置信度、地图（选中路线真实 polyline）、Q 值点图、状态特征、四策略对比（带簇/碳规则）、逐段碳分解（带簇/碳规则）。
6. Q 值图横轴会自动放大；四策略很接近时，点越靠右（越接近 0）越好。

## 12. 边界与未闭环

- **不是实时高德**：不调 REST，只用缓存 polyline 与缓存四策略指标；实时接口在本机多次 60 s 超时，故降级。
- **四策略共享几何**：地图画的是主路线，不能把四条线画成四条不同几何；页面已注明。
- **不是逐段实测速度**：每段速度取整条路线均速；真实逐段速度要等 OBD/交通流。
- **不做同趟多段**：历史只有整趟均速，无法在一趟内切多段；OBD 数据足够后才可能。
- **路线级簇是代理映射**：按候选均速/里程与 OD 中位载重映射，不是逐段聚类；同一 OD 四策略多数同簇（仅 11/310 跨簇）。
- **簇×载重 n<30 回退**：6 个可用格覆盖 99.4% 的趟；剩余 72 趟走 5 档 × 4 载重带，不拿单样本定规则。
- **不写 E₀、不进闸门**：演示通道只读缓存表，主账仍是 2,258,438.376 kg。
- **Q 是离线排序器**：四策略候选集固定；候选集之外的路线不会被发现。
- 收费按段等分、坡度 0 是简化；长途过路费分摊到段只是展示，不用于财务。
