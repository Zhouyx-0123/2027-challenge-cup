## 1. 数据设计

- **8 台车 × 5 天 × 250 点 = 10,000 条**，采样间隔 30 秒；每天 1 趟（TRK-SH-004/005/007/008 为城市短途，其余高速干线），共 **40 趟**。
- 车型覆盖（各 2 台）：31t 半挂（TRK-LOOP-001、TRK-SH-002）、18t 厢车（003、004）、12t 厢车（005、006）、4.5t 轻卡（007、008）。
- 车辆与车牌：TRK-LOOP-001/苏A12345（与固件、`config/devices.json` 同名）、TRK-SH-002…008。
- `ts` 带 `+08:00`；网关落盘会归一成 UTC（测试时可直接验证这一条）。
- `qc_flags` 在原始流里留空（板子不上报这一列，由网关写）。

## 2. 物理一致性（为什么不会出现「1000 g 碳跑 1 万公里」）

瞬时油耗不是随机数，而是按整备质量 + 载重 + 车速的稳态模型再加噪声：

```
instant_fuel_lph = 1.9 + 0.085·v + 6.5e-6·(m_curb + m_load)·v      （±3% 噪声）
冷机前 12 个点 ×(1 + 0.12·e^(-i/12))；怠速 n≈1.9 L/h
```

标定值（生成器里逐条断言）：

| 车型 | 满载总重 | 车速 | 油耗 | 折合 |
|---|---|---|---|---|
| 31t 半挂 | 44 t | 70 km/h | ≈27 L/h | ≈39 L/100km |
| 18t 厢车 | 26 t | 65 km/h | ≈18 L/h | ≈28 L/100km |
| 4.5t 轻卡 | 7 t | 70 km/h | ≈11 L/h | ≈16 L/100km |
| 重载城市 | 44 t | 20 km/h | — | ≈46 L/100km |

三条硬约束（生成时逐条断言，最大误差 0.0005）：

1. `odo_km` 逐点增量 = 同一行车速 × 30/3600；
2. `total_fuel_l` 逐点增量 = 同一行 `instant_fuel_lph` × 30/3600；
3. 碳 = 油耗 × **2.63** kg/L（柴油 TTW），趟级碳强度必须落在 150–1800 g/km。

实际结果：**3,921.76 km｜961.18 L｜2,527.90 kgCO₂｜644.6 g·km⁻¹**，趟级 418.3–970.5 g/km，油位全程 10%–100%。

用项目自己的流水线复算（`--no-write`，不动 `data/processed`）：

```
原始记录  ：10000 条（可用 10000 / 不可用 0）
车辆 / 行程：8 台 / 40 段
总碳排    ：2524.7679 kgCO₂e｜总里程 3921.34 km｜总油耗 959.988 L｜643.85 gCO₂/km
质控标记  ：engine_cold×121
```

与生成器差 0.12%，来自 CSV 里 `total_fuel_l` 保留 3 位小数的累计舍入，属正常。

### 4.1 必须知道的口径问题（代码级，已核实，未改代码）

`src/fleet_efficiency.py:109-118` 的 `diesel_kg_per_l()` 返回 **TTW + WTT = 2.63 + 0.53 = 3.16**；
而 `:203 _g_per_km_to_l_100km` 与 `:594` 用它把「TTW 碳」折成「理论 L/100km」。
分母多算了 WTT，**理论油耗被系统性压低 20.2%，偏差恒为 +20% 左右**——所以前 12 列有 7 台车「偏高/异常」。

本表**没有改项目代码**，只在右侧并列 3 列用 2.63 复算：口径一致后 6 台正常、1 台偏高（+17.6%）、1 台异常（+34.8%），与投放的 bias 对得上。
判定请以后 3 列为准；是否把 `diesel_kg_per_l()` 改成只取 TTW（会动 `tests/test_fleet_efficiency.py` 里 33.416 等断言），另行评审。

### 4.2 故意注入的分支

- **苏A12346（TRK-SH-002）**：油卡多买 33.5% → 异常·偏高；
- **苏A12348（TRK-SH-004）**：多买 18.2% → 偏高（关注）；
- **苏A12350（TRK-SH-006）**：跳过 2026-11-01 的加油票 → 部分趟次无油量覆盖，偏差 −9.46%，用来测「缺票/未覆盖」；
- 其余 5 台在 ±10% 内 → 正常；
- 121 个 `engine_cold` 点（每天头几个点暖机）→ 测质控标记。

## 5. 怎么用

### 5.1 直接跑 OBD 流水线（不动 `data/processed`）

```powershell
cd D:\oceanbase02\2027-challenge-cup
$env:PYTHONIOENCODING='utf-8'
python -m src.obd_pipeline --from-csv data\sim\excel_10000\obd_stream_10000.csv --no-write
```

去掉 `--no-write` 才会覆盖 `data/processed/obd_*.parquet` 与 `obd_summary.json`（会顶掉现有 6,600 点 demo 基线，测完请从 `_runs/` 或 git 恢复）。

### 5.2 走真实网关（板子 / Postman / curl）

```powershell
python server.py                                  # :5000，SENSOR_AUTH=0 时免令牌
curl -X POST http://127.0.0.1:5000/api/upload_obd_gps `
  -H "Content-Type: application/json" --data-binary "@data/sim/excel_10000/obd_board_batch_30.json"
```

返回 `{"status":"success","accepted":30,"rejected":0}`，落盘 `data/raw/obd_gps/obd_stream.csv`（26 列，`ts` 已转 UTC）。

### 5.3 用 Excel 自己扩到任意条数

`05_随机扩展模板` 全是纯公式（`RAND / RANDBETWEEN / ROUND / TEXT / DATE / TIME / ROW`，无 `NORM.INV`，兼容 WPS）：

1. D 列车速公式向下拖到需要的行数；
2. 全选 → 复制 → **选择性粘贴「数值」**（否则 `RAND` 每次重算，导出的 CSV 会变）；
3. 看「合理性判定」列：必须全 OK；出现「超界·检查」说明该行车速/油耗组合物理上不成立（g/km >1800 或 <150）；
4. 补齐 01 页其余列 → 另存 CSV UTF-8 → 回到 5.1。

真实车辆碳强度参考（判别数据是否离谱）：轻型柴油货车空载 200–350 g/km、满载 350–600；重型半挂满载 900–1300、空载 450–650。

## 6. 边界

- 不能把这份数据写进 E0 / A4 / 披露材料；它只用于跑通链路与压测。
- 04 页前 12 列是「项目代码原样输出」，含 20.2% 口径偏移；**不要拿它当数据质量结论**。
- 数据期 2026-11-01~05，与历史运单（2023）、现场 OBD 样本（2026-11-07）都不重叠——这是刻意的，避免污染既有对账。
- CSV 是 UTF-8 BOM；若下游按严格 UTF-8 读，先 `encoding='utf-8-sig'` 或剥 BOM。
