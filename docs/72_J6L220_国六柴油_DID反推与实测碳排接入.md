## 1. 手上到底有什么

| 项 | 内容 |
|---|---|
| 文件 | 29 个 all_*.csv（all_640/657…759）+ 1 个 raw_640.csv |
| 帧 | 39,645 帧（29-bit 扩展 CAN，**ISO-TP** 传输） |
| 请求/应答 | 0x18DA00F1 请求 → 0x18DAF100 应答（**物理寻址，地址 0x00**）；另有第二 ECU 0x21（0x18DA21F1/0x18DAF121，346 帧未展开）；心跳 0x18DB33F1「02 3E 87」 |
| 有效应答 | 18,619 条 0x62（肯定响应），覆盖 83 个 DID；请求→应答延迟 p50 = 12 ms、max = 116 ms |
| 分段 | 文件是多次采集的**拼接**（seq 回绕 / timestamp 归零切段），共 695 段；最长一段 660#122 = 688 s |
| 时钟 | **没有绝对时间**：只有每段内的相对 ms。接实车时用 --ts-base 传入段起点，否则 ts 留空并置 qc=clock_unknown |

**轮询结构**（这是最有用的一条线索，直接暴露了“哪两个量是仪表主页”）：

```
快通道  0x0165(rpm) 与 0x0166(喷油量) 各 5 s 一次，互相错开约 1.3 s   ← 仪表实时显示的两个量
第 1 页 每 20 s 固定 33 项，顺序固定：
        0193 0199 0152 01CA 026E 0124 0131 014D 01A5 015E 02D9 012D 0268
        01BA 01BB 0194 0195 0121 01B9 01DD 02A3 01AD 02EE 029A 017F
        0129 012B 01B1 016F 01F7 01B2 01E3 0120
第 2 页 约每 120 s 一轮：0180 01D7 0127 01DE 0156 0134 0270 0272 01D8 01D9 …
```

⇒ 上位机是把 ECU 的“数据流页签”一页一页轮询下来的。这解释了为什么 0x0165/0x0166 采样最密，也解释了为什么同一 DID 在不同段里缺采样。

**标识类 DID**（多帧，全部在 0x18DAF100 上应答）：

| DID | 内容 |
|---|---|
| 0xF802 | VIN = **LFNAFULXXN1E17982**（17 字节 ASCII，多段重复一致，可信） |
| 0xF804 | 10 字节 ASCII **100009E62F**（零件号候选） |
| 0xF80B | 39 字节标定/学习块（0x0EBB/0x0EBC 成对出现），不参与碳核算 |
| 0xF401 / 0xF806 / 0xF810 | 单调计数器 977,664→977,730 / 常量 1,239,477,104 / 常量 1 |

## 2. 没有 DID 手册时的反推方法（五类判据）

单看数值范围猜不出 DID，必须用**互相独立的证据交叉**：

1. **页面结构**：轮询顺序、采样周期、成对出现（actual/setpoint、上游/下游温度）本身就是语义线索。
2. **量纲守恒**：能把两个量相乘/相除凑成物理恒等式（例：每循环喷油量 × 转速 = 质量流量）。
3. **单调性**：累计量（油耗、里程、工作时间）必须整包单调；非单调的直接排除。
4. **相关性 / 积分自洽**：快变量之间用段时间序列相关（例：排温 vs 转速 0.77）；缓变量用“差分 vs 积分”。
5. **停车/行驶对照**：同一 DID 在纯怠速段与行驶段的分布差异（例：停车恒 0 ⇒ 车速/流量类）。

> 经验：单个判据都会错。本批里 0x0199 三次被误判成“里程”，最后是“Δ速率与转速无关（corr 0.056）+ 反推车速 124 km/h 与挡位不自洽 + 纯怠速段计数不动”三条一起才定成“行驶累计油耗”。

## 4. 关键一次判定：0x0199 是“行驶累计油耗”，不是里程

三条独立证据：

**(a) 纯怠速段计数完全不动。** 660#2 的 0x0199 在 3,002,042 上停了 4,134 s，其中 t=3444–4140 是连续 11.6 min 怠速（rpm 700、轨压 549 bar、喷油量 165–193）；664#16 与 661#29 两段纯停车怠速 Δ=0。若它是“含怠速的总油耗”，11.6 min 怠速应增 ≈22 计数。

**(b) 行驶段 L/计数 高度一致。** 用“喷油量×转速”积分做分子、Δ计数做分母（`tools/j6l220_calibrate.py`）：

| 段 | 时长 s | 积分油耗 L | Δ0x0199 | L/计数 | 若当里程反推车速 |
|---|---|---|---|---|---|
| 660#122 | 685.8 | 3.4794 | 182 | **0.01912** | 95.5 km/h |
| 669#5 | 115.2 | 0.7431 | 38 | **0.01956** | 118.8 |
| 672#6 | 185.2 | 0.4866 | 24 | **0.02028** | 46.7 |
| 729#0 | 85.0 | 0.1656 | 8 | **0.02070** | 33.9 |
| 671#3 | 120.1 | 0.7711 | 36 | **0.02142** | 107.9 |
| 661#65 | 140.3 | 0.8452 | 48 | **0.01761** | 123.1 |
| 660#2（64% 怠速） | 4651.4 | 2.0239 | 54 | 0.03748 | 4.2 |
| 664#16（纯怠速） | 175.1 | 0.4279 | **0** | — | 0 |

6 个长距离行驶段的 L/计数 落在 **0.0176–0.0214（中位 0.0199）**；11 个行驶段整体中位 **0.0214**、CV 0.20。只有“与距离无关的量（油耗）”才会这么稳；若它是里程，L/km 会随载荷/车速大幅漂移（本批从 4 km/h 蠕行到 118 km/h 都有）。怠速段偏大（0.0375）正说明计数器**不计怠速油耗**，与 (a) 完全一致。

**(c) 里程假设自相矛盾。** 660#122 内 0x0199 的 20 s 增量对应“车速”，在同一段里给出 rpm 1289→1837 时“车速”反而从 90 掉到 10；且 corr(Δ速率, rpm) = 0.056，corr(Δ速率, 喷油量) = 0.916。

⇒ 结论：0x0199 = **行驶累计油耗**，约 **0.02 L/计数**（待 CAL-1 加油定标确认）。绝对值 3,002,042 计数 × 0.02 ≈ **60,041 L**，按 25 L/100 km 折 ≈ 24 万 km，与 VIN 2022 年款、4 年营运自洽。

> 重要：因为它不含怠速，**不能**用 `Δ0x0199 × 0.02` 当“总油耗”；出账用 0x0166×0x0165 积分（含怠速），或用 0x0199 只做**交叉校验**。解码器在未给定 `--assume-0x0199-scale` 时 total_fuel_l 强制为 null。

## 5. 油耗主通道：0x0166 × 0x0165

四冲程 6 缸，喷油次数/秒 = rpm/2 × 6 / 60 = rpm/20：

```
q_mg_per_stroke × (rpm / 20) × 3.6 / (1000 × 0.835)  =  L/h
即  L/h = q_mg × rpm × 2.1557e-4      （q 原始计数 0.1 mg ⇒ ×2.1557e-5）
```

三个校验锚点（全部对得上）：

| 工况 | 0x0165 | 0x0166 | 换算 | 合理性 |
|---|---|---|---|---|
| 怠速 | 700 | 155（15.5 mg） | 0.54 g/s → **2.3 L/h** | 6.8 L 柴油机怠速 2–3 L/h ✓ |
| 660#122 巡航 | 1449 | 590（59 mg） | 4.27 g/s → **18.3 L/h** | 若 ~96 km/h ⇒ 19 L/100km ✓ |
| 带挡滑行（断油） | 1651 | 1（0.1 mg） | 0.03 L/h | ECU 真回 1，公式自动归零，不用另做断油判别 ✓ |

整批统计（1,370 个 5 s 快通道点）：p50 **3.34 L/h**、p95 32.1、max 55.5；抓包窗口内积分合计 **13.61 L**，87 段有油耗；仅 1 处断档被 MAX_GAP_S=90 s 截断。

**端到端联调**（tools/j6l220_contract_check.py：解码 → 契约校验 → src/obd_gps.py 官方守恒法）：
1,370 条记录里 1,271 条通过校验、99 条因缺 rpm 无法算油耗被拒（missing_fuel，占 7.2%），
通过的点合计 **13.5302 L → 35.584 kg CO₂**，权威因子 2.63 kgCO₂/L、守恒推导偏差 0.628%（与项目文档一致）。
与解码器自己积分的 13.61 L 差 0.6%，来自段边界与缺样处理——两条链路互相印证。

碳排（config/calc_factors.json，diesel_ttw = 2.63 kgCO₂/L）：

```
13.61 L × 2.63 = 35.8 kg CO₂    （解码器口径，本次抓包窗口）
13.5302 L × 2.63 = 35.58 kg CO₂ （官方守恒法口径，1,271 条有效点）
60,040.8 L × 2.63 = 157.9 t CO₂ （车辆全生命周期计数器口径，仅作量级参考）
```

> 功率校验留个心眼：max 样本 q=150.3 mg @ 1730 rpm ⇒ ≈220 kW，超过 J6L220 额定 162 kW，可能是单点异常。建议出账前按 p99 截尾（或直接用契约 NUMERIC_RANGES 卡）。

## 6. 缺什么、怎么补

| 通道 | 现状 | 补法 |
|---|---|---|
| vehicle_speed_kmh | **本批没有**。29 个文件里找不到任何“停车=0、行驶随工况、0.1 km/h”的量；0x0199 已排除；0x0124/0x015E/0x017D 停车为 0 但幅值与 rpm 无稳定关系 | ① 上位机切到含车速的页签重抓；② 用标准 OBD mode 0x01 PID 0x0D；③ 向服务站要 J6 数据流 DID 表 |
| odo_km | 无（0x01B9/0x01D8/0x01D9 非单调） | 同上，或用 GPS 里程 |
| atm_press_kpa | 无（0x0125/0x014B 判常量） | ECU DID 或 GPS 海拔换算 |
| engine_load_pct | 无 | 用 q 与额定喷油量之比近似，或用 0x016F（需定标） |
| 绝对时间 | 无 | 采集端给 `--ts-base`（ISO8601 带时区） |

**定标清单**（写进映射表 `calibration`，按顺序做）：

- **CAL-1**（最关键）：记录 0x0199 初值 → 加油 200 L（油枪读数）→ 再读。若 Δ计数 ≈ 200/0.02 = 10,000 且与仪表“累计油耗”一致 ⇒ 确认 0.02 L/计数；若 Δ计数×0.1 = km ⇒ 翻案成里程。
- **CAL-2**：满负荷（额定转速、油门到底）读 0x0166，与额定功率/BSFC 对表，确认 0.1 mg 刻度并定 max 合理上限。
- **CAL-3**：冷启动到热机，同时读 0x012B 与仪表水温，确认 ℃ 刻度。
- **CAL-4**：加油前后读 0x01D7，确认 % 刻度与油箱容积（J6L 约 300–400 L）。

## 7. 怎么用（复现命令）

```powershell
# 1) 自检（3 个油耗锚点、单帧解码、多帧 VIN 重组、映射表校验）
python src/obd_did_j6l220.py --selftest

# 2) 全量解码：契约行 + 逐 DID 序列 + 摘要
python src/obd_did_j6l220.py --input "<解压目录>" --series outputs/obd_j6l220/did_series.csv

# 3) 定标体检：逐段“喷油积分 vs Δ0x0199”
python tools/j6l220_calibrate.py --input "<解压目录>" --out outputs/obd_j6l220/calibration_segments.csv --json outputs/obd_j6l220/calibration_verdict.json

# 4) 演示：假定 0.02 L/计数 时的 total_fuel_l（仅演示，未定标不得入库）
python src/obd_did_j6l220.py --input "<解压目录>" --assume-0x0199-scale 0.02 --out outputs/obd_j6l220/decoded_points_assumed.csv

# 5) 端到端联调：解码结果 → 契约校验 → 项目官方守恒法算碳（合成时间轴，仅联调用）
python tools/j6l220_contract_check.py --input "<解压目录>" --out outputs/obd_j6l220/contract_stream.csv

# 6) 有绝对时钟时
python src/obd_did_j6l220.py --input "<解压目录>" --ts-base 2026-11-11T09:00:00+08:00 --out ...
```

产出的契约行字段与 config/obd_gps_contract.json 对齐：
`ts, vehicle_id, fuel_type, instant_fuel_lph, engine_rpm, throttle_pos_pct, fuel_level_pct, engine_temp_c, total_fuel_l, odo_km, vehicle_speed_kmh, atm_press_kpa, engine_load_pct, counter_0x0199, seg, t_s, qc`

缺的通道一律写 null，并在 qc 里标 `<channel>_absent`；时钟缺失标 `clock_unknown`；`counter_scale_unverified` 表示该行 total_fuel_l 不可直接入账。

## 8. 边界与风险

1. **不碰主口径**：本通道是并列证据链，不改 src/pipeline.py、不改 28 条判据、不写主结果表；产物只落 outputs/obd_j6l220/。
2. **0x0199 未定标**：映射表 `scale` 已按实测填 0.02，但 status 是“待 CAL-1 确认”，解码器只有显式传参才写 total_fuel_l。
3. **排量假设**：油耗公式只依赖“每循环喷油量×转速”，与排量无关；但功率反推用固定 BSFC 200 g/kWh，仅作合理性校验。
4. **采样是 5 s**：瞬时峰值会被漏采或放大；碳账用积分，不用单点乘时间。
5. **第二 ECU（0x21）**：346 帧尚未展开，可能是仪表/后处理控制器；若后续要 DPF/尿素数据，先解这个 ECU。
