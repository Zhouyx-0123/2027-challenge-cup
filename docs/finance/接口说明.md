# 财务主表接口 v2

## 范围与状态

本轮完成33列Excel、发票类型/税率抽取字段扩展、JSON/CSV导入、JSON导出和五类按ID回填。现已提供整合包并接入前端登记与下载；未上传到GitHub。原有发票金额、税额及新增税率按票面保存，不推算、不预设13%。抵扣资格与票面信息分开。

依赖沿用原项目的openpyxl（本地验证3.1.5）；OCR源码另需原项目既有requests及其他依赖。导入、导出、回填不调用大模型。OCR提示词增加字段，不额外发起请求，但单次提示词长度略增。

## Python入口与命令

- `tools/invoice_to_master.py`：`write_master(path, records, source_mode, dry_run=False)`。输入为原OCR字段字典列表；新增`invoice_type`与`tax_rate`可缺省。输出added、duplicates、rejected。有效记录可写入，拒绝记录不写；调用方必须查看报告。
- `tools/finance_master_interface.py`：`export_master(path, mode)`返回JSON对象；`apply_updates(path, envelope, dry_run=False)`回填。回填任何一项不合格整批不写。
- `source_mode`必须为`simulated`或`real`，一个工作簿不能混用。原三条演示数据是模拟，真实导入应使用另一份空白工作簿。

项目根目录下执行（全部是本地操作）：

```bash
python tools/invoice_to_master.py --input examples/finance/invoices.json --output outputs/finance_demo.xlsx --source-mode simulated --report outputs/import_report.json
python tools/finance_master_interface.py export --master outputs/finance_demo.xlsx --output outputs/finance_export.json --source-mode simulated
python tools/finance_master_interface.py apply --master outputs/finance_demo.xlsx --input outputs/updates.json --dry-run
python tools/finance_master_interface.py apply --master outputs/finance_demo.xlsx --input outputs/updates.json
python -m unittest discover -s tests -p 'test_finance*.py'
```

首次导入可以创建新表。导入现有表时必须是33列v2模板；旧28列表不会被静默迁移。导出包含完整33字段，金额和数量用十进制字符串，未知为null；税率数字例如`"0.13"`，免税/不征税等保留文字。日期为YYYY-MM-DD，月份为YYYY-MM，回填审核时间须带时区。

## 回填合同

```json
{
  "schema_version": "finance_master_v2",
  "source_mode": "simulated",
  "kind": "association",
  "source": "activity_module",
  "reviewer": "实际审核人",
  "reviewed_at": "2026-10-31T12:00:00+08:00",
  "reason": "运单与发票核对依据",
  "updates": [{
    "record_id": "从导出结果复制实际记录ID",
    "expected": {"activity_id": null, "waybill_no": null},
    "values": {"activity_id": "ACT-001", "waybill_no": "WB-001"}
  }]
}
```

上例只是形状说明，不能以占位ID直接执行。`expected`必须完整覆盖本次`values`字段；应从最近一次导出读取旧值。接口按record_id查找，不依赖Excel行号。不允许修改发票原始字段。重复提交相同结果不再追加记录；原值冲突、未知ID、重复ID、错误类型整批拒绝。每次实际变更写入同一工作簿的“接口回填记录”，保存原值、新值、来源、审核人、时间和理由，与主表一并原子保存。

|kind|可回填字段|主表列|约束|
|---|---|---|---|
|association|activity_id / plate / waybill_no / trip_id / run_id|B/S/T/U/V|仅可靠关联后写入；不能将一张票整额复制给多个趟次|
|verification|verification_status / posting_allowed / reviewer / reviewed_at|W/X/Y/Z|四字段同时传；posting_allowed用true/false/null；待核验或异常不能标true|
|deduction|deduction_status / deductible_input_tax / deduction_basis|AE/AF/AG|三字段同时传；待确认金额null；不可抵扣金额0；可抵扣金额不能超过票面税额|
|cost|confirmed_cost|R|非负且至多两位小数；核算依据填批次reason，留在回填记录；不自动决定成本金额|
|classification|expense_category|J|燃料、电力、路桥、维修、碳配额购买、履约、其他、待分类|

抵扣接口只接收外部已经作出的判断并检验内部一致性，不判断企业纳税身份、发票抵扣资格，不执行税务申报。双验接口不运行PM的核验算法。导出不会过滤未审核记录，下游正式计算必须自行依据posting_allowed与业务条件筛选。

## 运行边界

这是可信本地模块/CLI接口，不是公开HTTP服务。`source`是审计标签，不是身份认证。一个工作簿同一时间只允许一个写入者；运行时关闭Excel编辑，避免文件锁和并发覆盖。票面缺号码/日期/价税合计、冲突重复、负数红字等转复核。当前按单项目票登记；多明细、多税率、红冲与跨趟分摊尚未自动化，不能声称全部票种均支持。输入明确标记multiple_items或items含多项时会拒绝；未标记的复杂票仍需人工识别。
