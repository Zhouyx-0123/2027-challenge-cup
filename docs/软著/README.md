```text
碳慧智算物流碳感知智能决策系统 V1.0
```

- 申请表、源代码页眉、用户手册封面三处必须完全一致。
- 版本号是否带 V，以申请表为准；三处保持一致。
- 不要用“Carbon Tide”作为登记名称；它只是内部设计代号。

## 必须补齐的 5 件事

### 1. 源代码 60 页

- 前 30 页 + 后 30 页，每页不少于 50 行；
- 每页页眉：软件名称 + 版本号 + 页码；
- 只放原创 Python 代码：`app/`、`src/`、`tools/` 的核心文件；
- 不放 `tests/`、`data/`、`config/*token*`、第三方库源码、密钥、客户/运单原始数据；
- 当前约 20,016 行，按 50 行/页约 400 页，足够取前后各 30 页；
- 源代码中不得出现 API key、数据库密码、内网地址、个人手机号。

### 2. 用户手册 60 页

- 每页不少于 30 行；前 30 页 + 后 30 页；
- 内容：系统概述、运行环境、安装启动、数据准备、8 个页面操作、碳模型口径、台账/披露、常见问题；
- 截图必须脱敏：不出现客户名、真实运单号、车牌、手机号；
- 手册封面写登记名称/版本，页脚写页码；
- 现有 `README`、`docs/30`、`docs/37` 可做素材，但不能直接当 60 页手册。

### 3. 权属确认

- 申请人是个体、团队、学校还是公司？
- 团队成员是否签署著作权归属/转让协议？
- 如果是课程/竞赛/委托开发，是否属于职务作品或委托作品？
- AI 辅助生成部分是否有人类实质性修改记录（commit、设计文档）？
- 若使用学校资源/导师课题，先确认学校是否主张权利。

### 4. 数据与第三方合规

- 京东/比赛运单数据：**不要提交原始数据**，截图脱敏；数据使用权与软件著作权是两件事；
- 高德/OSM：不提交地图瓦片、不提交 key；OSM 保留 `© OpenStreetMap contributors`；
- Streamlit、pandas、pyarrow 等开源库：不把库源码当自己的代码提交；保留依赖清单与许可证说明；
- UI 参考了 Scrolltide/Coolors 的风格，但不要复制其代码/图片/字体；当前无外部图片字体，风险较低。

### 5. 申请表信息

- 软件全称/简称、版本号；
- 开发完成日期、首次发表日期（未发表/已发表必须真实）；
- 开发方式：独立开发/合作开发/委托开发/下达任务；
- 权利取得方式：原始取得/受让/承受/继承；
- 申请人身份证明（营业执照/事业单位法人证书/身份证等）；
- 合作/委托/任务开发，附合同或任务书。

## 不建议现在直接提交的原因

1. 没有 60 页正式手册，容易被要求补正；
2. 源代码没有统一页眉/页码/50 行排版；
3. 权属未确认，尤其是团队/学校/比赛数据；
4. 软件名称和版本在 UI、README、代码里不完全统一；
5. 数据与第三方地图/开源库边界没有写清。

## 建议顺序

1. 定名称与版本：`碳慧智算物流碳感知智能决策系统 V1.0`；
2. 生成源代码前后 30 页（50 行/页、统一页眉）；
3. 写 60 页用户手册（30 行/页、截图脱敏）；
4. 签团队成员权属确认；
5. 在版权保护中心在线填报、上传、提交；
6. 拿到受理号后跟踪补正。

## 重要边界

软著保护的是**代码表达**，不保护 VSP 算法、Pareto 选路、碳价权重等**思想/方法**。
如果这些是项目创新点，软著之外还应考虑论文、专利或技术秘密；软著不能替代专利。
